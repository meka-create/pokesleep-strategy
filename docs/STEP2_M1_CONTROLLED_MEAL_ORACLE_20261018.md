# STEP 2 M1 — 生産・回収・料理・げんき回復の独立1分時計算（2026-10-18）

対象：`scripts/step2-m1-controlled-meal-oracle.cjs` と `tests/step2-m1-controlled-meal-oracle.test.cjs`。

**用途はB級の人工制御条件の検証。M02/M04のゲーム実測ではない。M1 PARTIAL／STEP2 HOLD／STEP3未着手。**

## 目的と独立性

従来の[きのみのみ検算](STEP2_M1_CONTROLLED_RANKING_ORACLE_20261018.md)は、食材・料理・スキルをすべてOFFとしていた。今回のCM01/CM02は、**食材を生産し、回収し、実際に鍋で消費し、料理エナジーとげんき回復を計算する7日間**を、新しい1分刻みの独立時計算で照合する。

- CM01：固定昼チームと固定睡眠、初期リンゴ7個で初回朝食可能。
- CM02：朝・昼・夜で日中編成を入れ替え、初期リンゴ0個で初回朝食を実行できない。
- 全個体Lv50・まじめ・サブスキルなし。ライチュウのおてつだい結果は必ず**第1枠リンゴ1個**、フシギダネは必ず**きのみ1個**となるよう種族の食材抽選率をそれぞれ人工的に100%・0%にする。全種メインスキル抽選率0、所持数上限100万、共通食材バッグ上限なし（所持枠溢れと相関を排除）。変更した種族マスターは `finally` で元に戻す。
- ゴールド旧発電所・FB25%、固定睡眠0:00〜7:30、睡眠スコア80、初期げんき30、いいキャンプOFF。レシピはとくせんリンゴカレー（リンゴ7個、Lv70基準強さ2678）。料理は各日朝・昼・夜の最大21機会、ほかのレシピ・追加食材・大成功・イベントなし。鍋は57個。
- 別実装は毎分げんきタイマー・おてつだい進捗を更新。各回収で個体ポケットの整数リンゴ/きのみを回収し、残高不足なら料理不成立（食品・料理エナジー・げんき回復なし）、成立時のみ食材7個消費、料理エナジー付与、げんき帯に応じ回復。交代時の進捗・タイマーを破棄。
- 日曜24:00→月曜04:00は稼働するが未回収。実際に回収した食材数と未回収の食材数は別管理し、週間エナジー・食材残高に未回収分を混ぜない。
- 種族の基礎速度・タイプ・Lv70レシピ基礎エナジーだけを同じマスターから使う。おてつだい完了・げんき速度帯・回復量・きのみエナジー・料理条件・週境界は `src/simulator.js` の関数を呼ばずに別実装。

## 比較項目

二つの7日間について週間 `berries`・`cooking`・`total`、料理回数、**日付／朝昼夜の成立順序**、回収リンゴ総数・料理消費リンゴ・期末在庫が独立参照値と一致すること。スキルといつのまに育成は0でなければならない。

`npm run m1:controlled-meals` で `M1_CONTROLLED_MEAL_JSON=` 行に機械可読な結果を出す。CIで得た参照結果は確認後に追加し、確認前の数値は確定扱いしない。

## 証拠の限界と次の段階

これは**食材抽選を0%/100%に置換した人工状態**。現実のポケモンのランダム食材・ストック溜まり・食材バッグ・スキル・複数種類の食材の相関、大成功、実ゲームでの料理成立率は検証していない。M02/M04の週間数値は依然C級・独立参照なしであり、14条件の限定B級10件＋未検証4件、R01〜R05順位は全件未検証を変えない。

人工条件での不一致があった場合はモデルと参照時計算の両者を監査してP0/P1/P2に分類し、未検証の修正を闇雲に適用しない。
