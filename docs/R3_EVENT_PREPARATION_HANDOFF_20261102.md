# R3 イベント前の準備 → 日曜実績 → 本番計画（2026-11-02）

## 決定方針
- 準備週にはパーティを提案せず、食材と鍋拡張・スキル待機の目標を提案する。
- 日曜夜に実際の食材、鍋の拡張量、個体別スキル待機を入力し、翌週のイベント週の計画の初期条件へ反映する。
- 月～日の21枠と睡眠7晩の自動編成は従来の週間編成機能に委ねる。

## v0.5.7の実装範囲
- 指定料理1～21食の総需要と、先頭3食の食材備蓄目標を分ける。3食がバッグ容量に入らないなら不足を表示。従来の30%/90%を使用しない。
- 鍋拡張の最低目安は先頭料理の必要枠と通常鍋容量との差から算出。発動保証や技能発動率を推定しない。
- 実際の食材19種、鍋拡張+0～200、スキル待機個体/回数/確認状況を独立保存。旧JSON version:1を維持する。
- 実際の在庫と初回の鍋拡張から、最初の3食を入力順に評価する。今後の食材獲得を確定扱いしない。
- 明示的な反映操作で初期食材/バッグ容量だけを週間シミュレーターへコピー。基本編成と曜日別21枠・睡眠7晩は変更しない。
- 準備週の旧パーティ推薦、30/90%比較、準備週の参考7日試算は通常UIから隠し、コード/旧保存値を互換資産として維持する。

## 未実装・評価上の制限
- 鍋拡張とスキル待機数は週エナジー最適化の開始状態にまだ渡せない。記録済みでも週間スコアに反映済みと主張しない。
- イベント食事カテゴリがランダムな週では、登録レシピの成立可否はカテゴリが一致する場合に限る。
- 21食全体の順序、週内食材獲得、料理成立確率、イベント特殊効果、2週間持ち越しは未モデル化。
- パーティ/計算器の独立実ゲーム順位精度HOLDは引き続き維持。新UIのAndroid Chrome実機受入は別途必要。

## 次工程
1. v0.5.7 UIと保存の自動回帰、CI、Android Chrome受入。
2. 鍋拡張初期値の週間モデル接続、スキル待機・おてつだいストックを検証済み範囲から順次接続。
3. 日曜入力から翌週21枠+睡眠7晩、料理の最終計画をまとめて提案する体験の完成・R5厳密監査。
