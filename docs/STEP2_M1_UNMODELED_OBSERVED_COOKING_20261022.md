# STEP2 M1：試算料理エナジー0対実測正値の比較保留（2026-10-22、v0.2.66）

## 再現
料理レシピを選択していない固定モードで7日間を試算すると、`simulated.cooking===0`になる。一方、ゲーム週間まとめの料理欄に正のエナジー（例40）が入力されても、従来の`knownModelLimitations`は両者の料理内訳の非対応を特定しなかった。チェックボックスがすべてtrueでモデル診断カウンターが整い、総数と2欄が一致する人工例では`UNCALIBRATED_OBSERVATION`へ分類できる。実際にレシピ未選択・カテゴリ不一致・食材不足・確率的な料理成立のいずれによる差か判定できないため、モデルの料理計上0を正の観測料理の参照値として扱うべきでない。

## 実装
- 共通 `knownModelLimitations(input,simulated,observedCooking)` に **observedCooking>0 && simulated.cooking===0** の条件を追加。原因を断定せず、料理モデルと観測の対象未照合として比較保留。
- `preview` は保存したモデルの料理欄、再読込は現在計算器の料理欄、CLI `m1:observe` も現在計算器の料理欄に観測料理エナジーを渡す。
- 観測・モデル双方の料理が0の場合、この新理由は付けず、従来の状態分類を維持。
- 自動料理選択・大成功期待値OFF・鍋依存など既存の独立保留条件は維持。
- 旧テストで「料理を試算していないのに実測料理が正」という人工の不整合を使っていた、他の限定チェック用fixtureを料理実測0に訂正。保存形式・週次エネルギー計算式・マスター・CSV16列は不変更。

## テスト・限界
