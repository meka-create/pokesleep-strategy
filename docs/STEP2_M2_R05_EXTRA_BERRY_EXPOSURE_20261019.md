# STEP 2 M2：凍結R05 vs 人工追加おてつだい交代ケースのきのみ未回収感度

2026-10-19 / v0.2.44 / **C級のモデル内診断のみ** / M1・M2・M3 PARTIAL / STEP2 HOLD / STEP3 NOT_STARTED

## 監査で見つかった適用範囲の違い

凍結されたR05の比較は「固定ヒーラー（A）vs 朝昼夜交代（B）」であり、選ばれた10個体の中に**おてつだいサポートS等の追加おてつだい生成スキルは存在しない**。したがってv0.2.43に追加した未回収キュー警告は、**元のR05には発生しない**。R05の本来の懸念は回復スキルの抽選・睡眠げんき・時間の相関と交代コスト等であり、v0.2.43を元R05の精度改善・校正済み証拠として扱わない。

## 独立した人工的な感度ケース

同一の固定睡眠5匹・同一フィールド・初期140個のリンゴ・同一時刻/鍋条件のR05形式を再利用。ただしA/B**両方**の `w0` 個体の種族を、マスター内の `Extra Helpful S` を持つ種に差し替えて計算する。これは実際の凍結R05を上書きせず、別の人工条件として扱う。

1. 通常モデルで両候補の `total` と、編成交代で未回収のまま消去された追加きのみ `bag.berries` を追う。
2. それぞれの未回収きのみ個数に、当該ポケモンのレベル・フィールドボーナス・好きなきのみに基づく現行モデルの **berryUnit** を掛けて加算した `uncollectedExtraHelpBerryEnergyAtSwap` を算出。これは*きのみだけ*の会計換算で、失われた食材は含めない。
3. 別途、**「両候補でこのきのみエナジーだけ全て回収済みとして加算し、その他は固定したら」**という算術感度を記録：`deltaAfter=deltaBefore+lostBerryEnergyB-lostBerryEnergyA`。

3は**実行可能な新スケジュールではなく、局所の足し算だけ**。追加でタップした際のスキル発動、時間経過、所持枠、料理・食材、げんき変化を再計算していない。**実ゲームの週間エナジーの上限/下限でも、ゲーム順位が逆転する確率でもない**。勝敗の表示は「モデル内の足し算前後」を示すのみ。

再現：`node scripts/step2-m2-r05-extra-berry-exposure.cjs`。テスト：`npm test` 内の `tests/step2-m2-r05-extra-berry-exposure.test.cjs`。JSONの `frozenOriginalR05` でR05元データと一致・未回収キュー0を固定し、`controlledAlternative` で追加おてつだいを含むモデルに限定した会計差分を検査する。

## 現在の結論

M1の14条件中、10件は限定人工B級照合、混成M01〜M04は実ゲーム未検証。凍結R01〜R05の元の順位は5組とも未検証。実ゲーム観測0件。追加おてつだいの実際の受取順・編成交代時の保持／再回収可否は未測定。独立したゲーム一次情報または実機で確認できない限り、この人工会計差分を元の週間モデルや編成推薦の計算へフィードバックしない。
