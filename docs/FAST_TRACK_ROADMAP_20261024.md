## 1. ユーザー決定の開発方式

1. **完成を最優先**：主要機能・現実に使えること・重大な誤計算を先に扱い、内部確率の完全再現、低優先度の微小誤差研究、根拠のない補助テストの増殖は後回しにする。
2. **同一会話でまとめて完遂**：同一STEPの関連作業は、調査→実装→必要な検証→修正→PR→CI→マージ→状況更新をできるだけまとめる。単独の小修正ごとに会話を切らない。作業規模が大きければ機能単位に分割する。
3. **通常時の検証を適正化**：変更箇所の単体試験、直接影響を受ける既存回帰、最低限のE2E、ビルドおよびCIを実施する。無関係なケースの精密な再現モデルや、似た人工オラクルの増設を新しい完了条件にしない。重大な計算式変更時は影響を受ける結果比較を追加し、バグと未検証を区別する。
4. **STEP終了の境界で必ず停止**：STEP完了候補の成果・既知制限・テスト・残課題を提示して開発を止め、**ユーザーが別途指示する厳密監査**を受ける。監査での重大指摘は同じSTEP内で修正・再監査し、**ユーザーが明示承認するまで次STEPを始めない**。中間の独立UI改修フェーズも同様。
5. **毎回の最終報告**：完成した内容、未完了、現在のSTEP/マイルストーン、次の具体的な1つ以上の作業を必ず提示する。新しい実測がないのに精度証明・順位証明の完了を主張しない。

### STEP移行と「完成」の区別

- **機能的な完成（使用可能）** と **ゲームに対する独立検証済みの高精度** は別概念。STEP2の完全な実ゲーム週間照合が未取得でも、重大不具合を排除し、計算できない条件を明示し、承認を得たら **「条件付きの機能完成」** としてSTEP3開発へ移行できる。
- この場合、計算器の一般精度や候補順位を「実証済み」「最適確定」と呼ばない。敏感な比較は差分の小ささ・未対応スキル・料理・2ヒーラー等の要因を表示し、**順位判定保留**または**参考順位**とする。
- **STEP2精度HOLDは実測精度の不確実性として残る**。監査による「条件付き機能完成」承認と混同しない。
- 重大な再現可能誤差（P0：架空の成果・二重計上・曜日/睡眠/週境界違反・主要効果欠落・無警告の危険な順位確定）は修正または該当比較を使用不能にすることが必要。P1/P2の近似は範囲と影響を明示し繰り越せる。
