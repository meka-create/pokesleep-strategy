# STEP 2 M2 — スキルストック・天井・げんき・減少タイマー結合の独立参照（2026-10-18）

## 何を検証するか

[2回回収×2ヒーラーの人工16分岐](STEP2_M2_E4_TWO_TAP_JOINT_ORACLE_20261018.md)では、各回収のスキル発動を独立Bernoulliとして与えた。しかしゲームに近いスキル判定を考える際は、**前の回収までの連続不発回数（天井までの残り）と待機ストック上限**が発動確率に影響する。

そこで今回は、**発動源1匹・受取側1匹・回収2回**の小さな制御モデルを追加する。確率的スキル抽選を含む4回のおてつだい完了（各回収前2回）、ストック上限1または2、不発天井3または5、げんき・10分減少タイマーを状態として引き継ぐ。

## 参照モデルの仕組み

`scripts/step2-m2-e4-stock-pity-oracle.cjs`

- 結合状態 `(げんき, タイマー位相, 連続不発回数, 待機ストック, 累計実発動)` を確率質量として追跡。ストック満杯中は追加抽選なし。指定の天井到達時は確定成功。発動確率0%はスキルなしとして天井も進めない。
- 各回収操作では、待機ストックに応じた整数回復18×発動回数をげんき150上限で制限し、実際にげんきが増えた場合のみ減少タイマーを0へ戻す。ストックは回収時にクリアするが、連続不発回数は保持する。回収後1分だけ進む。
- 独立な2実装として、**逐次状態DP**と**4つの抽選枠の16通りの列挙**を実装。両者の終端状態・個別確率・総質量1を照合する。
- 本体の `advanceSkillProcState`、`skillProcMarginal`、`clearSkillProcStock` は**比較対象としてのみ使用**し、参照DPの確率生成には利用しない。ストック期待発動回数が整合することも別に確認する。
- 4スロット16通りは**人工的におてつだい完了数を固定した条件**であり、実ゲームで2回の回収までに必ず2回ずつ完了することを意味しない。

## 誤解してはいけない点

これは**実測に基づく天井回数・抽選率ではない**。天井3/5、人工スキル率20%/25%はモデルの境界挙動を再現できるか調べるための入力である。実ゲームのストック・天井仕様を断定したものではない。
