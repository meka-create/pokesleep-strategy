# STEP 2 M2 — げんきオールS：期待回復と10分減少タイマーの相関（2026-10-18）

## 独立時計算で分かったこと

現行の週間計算エンジンは、メインスキルの待機ストックを確率分布で管理する一方、げんきと10分減少タイマーを**期待値1本**で保持する。スキルの期待回復が微小でも `applyEnergyRecovery` でげんき値が上昇すると、10分減少タイマーを0にリセットする。

これは「スキルが発動した分岐では時計を0へ、発動しなかった分岐では元の時計を維持する」有限分岐の計算と、必ずしも一致しない。発動確率が小さいほど、相関を失う影響が現れる条件がある。

[独立4分岐時計算](../scripts/step2-m2-e4-timer-oracle.cjs)は、発動イベント（2匹独立、各0/1回）と10分減少タイマーを分離して1分進める人工条件。参照側は `simulator.js` のタイマー関数を呼ばない。比較する期待値モデル側には現行の `applyEnergyRecovery` と `advanceEnergyTimer` を使用する。

**共通人工条件：** げんき100、減少タイマー9分、発動すれば各18回復、次の1分を進める。げんき150の上限には達しないため、これは[回復上限の別監査](STEP2_M2_E4_HEAL_CAP_JENSEN_AUDIT_20261018.md)と別の誤差源。

| 2匹の人工発動確率 | 4分岐の正しい1分後期待値 | 現行の期待値1本モデル | 差 |
|---|---:|---:|---:|
| 0% / 0% | 99 | 99 | 0 |
| 1% / 0% | 99.19 | 100.18 | **+0.99** |
| 1% / 1% | 99.3799 | 100.36 | **+0.9801** |
| 50% / 50% | 117.75 | 118 | **+0.25** |
| 100% / 0% | 118 | 118 | 0 |

この単一人工イベントに限ると、発動率を `p,q` とした現行期待値との差は `(1-p)(1-q)`。これは**条件付きの1分後げんきの差**であり、実ゲームの週エナジー誤差率・真のスキル発動率ではない。

## 実装（v0.2.34）

- `scripts/step2-m2-e4-timer-oracle.cjs`：独立有限4分岐参照と現行モデルの比較。任意の実測ゲーム確率は入力せず、試験用に明記した人工確率のみ使用。
- 週間E4／きのみジュースの回収操作で「スキル0回の確率が0と1の間」「期待回復量が正」「対象ポケモンの減少タイマーの残り位相が正」という条件を満たした局所回数を `healingTimerCorrelationEvents` として計測。
- 条件を満たした場合に限り、結果の警告に「未発動時のタイマー保持と期待値方式の差異／週間精度未検証」を表示する。
- **週間計算結果は変更しない。** 目先の平均タイマーへの修正は、離散的な0/1減少・げんき帯の速度境界と同時確率を正しく保存できないため、まず独立の有限状態モデルの検証を優先する。

## 限界・次の優先事項

- 上記の局所差はゲーム中の真の確率でも週間誤差の符号・大小の保証でもない。げんき上限、他の回復、連続した発動・料理・睡眠・編成交代によって結果は複雑になる。
- 実際の週間試算では15分などの回収間隔や他の回復で位相が動く条件に警告を絞る。150分などタイマーがきれいに揃うケースでは局所差が現れないこともある。
- **次に実装すべき最小検証**：1匹の受取側と最大2匹のE4発動元だけを対象に、`(げんき,10分位相,スキルストック)` の小さな結合状態を、複数回収操作にわたって独立時計算する。ゲーム実測を取得しない限り元のR02のA級順位は未検証。
