# M1 ボックス順序に依存する誤った観測比較ブロック（v0.2.65 / 2026-10-22）

## 問題
従来の比較キーはJSONオブジェクトのプロパティ順序を無視するが、配列の順序を保持する。これは「朝昼夜・睡眠の各5匹」の編成配列に対しては保守的に正しい一方、内部IDで識別される`input.box`の単なる並べ替えまで「ボックス内容が違う」と判定した。

例えばR02のプクリン1匹対2匹相当の異なる2週に同一の個体と設定を登録していても、一方のボックス個体を並び替えるだけで`NON_COMPARABLE`となり、同週再読込の`conflictingInputsMondays`にも誤検知を出す。比較用キーの問題であり、実ゲームの週間計算値の誤りを示すものではない。

## 修正
- R02のボックス比較に`comparableBoxKey`を適用。各個体を内部IDで安定ソートし、内部プロパティのキー順も既存の比較規則で正規化。
- 複数観測JSONの`sameSavedInputs`／`conflictingInputsMondays`も同様に`box`だけ正規化した`comparableSavedInputKey`を使う。
- チームの朝・昼・夜・睡眠配列の並びは正規化しない。個体レベル、スキル、食材、並び以外の入力変更は引き続き別条件・比較不可。データは読取専用で再書込しない。
- 各レコードの`validateReplayInput`で内部IDの欠落・重複・不正値を検出した後だけ適用する。

## 回帰の範囲
`tests/step2-m1-r02-two-week-screen.test.cjs`および`tests/step2-m1-observation-import-replay.test.cjs`に、順序逆転の正例・個体レベル変更とチーム配列変更の負例を追加。記録時再試算、ブラウザ再読込、CLIの比較経路との整合を確認する。
