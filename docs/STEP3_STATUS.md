# STEP 3 — 朝・昼・夜の自動編成（開始記録・v0.3.0）

開始条件：ユーザーが2026-10-25に **STEP2の条件付き機能完成とSTEP3の開発開始を明示承認**。STEP2最終監査PR #82とAndroid Chrome14/14受入PR #83を完了した状態から着手。ゲーム週間実測による精度HOLDは引き継ぎ、「最適確定」は禁止。

## 今回の範囲：S3-A 候補生成＋最小操作UI

- `src/step3.js` を新設。最新の種族マスターから認識可能な手持ち個体を選び、朝7:30～12:00／昼12:00～18:00／夜18:00～0:00の各5匹を生成。
- **A**：朝2匹・昼夜1匹の「げんきオールS系（全体回復スキル）」編成。昼12:00に必要な変更を行い、18:00の交代を省くパターン。全体回復系2匹・その他4匹がなければ候補を出さず理由表示。
- **B**：終日全体回復系1匹の同じ5匹（12:00／18:00の交代なし）。別ヒーラーがいれば代替B案。全体回復系1匹・その他4匹がなければ理由表示。
- **C**：きのみ生産の簡易指標による5匹、全体回復系0匹（可能なら）、固定睡眠5匹を日中も維持する0入替案。重複編成は除外。
- **固定睡眠5匹は生成/反映しても不変更。** 7:30の初回回収後の交代、12:00／18:00の任意交代、0:00前後に睡眠5匹へ復帰する場合の交代数を各候補に表示。
- 候補は**非ランキング**。簡易きのみ指標は候補を絞るためだけで、せいかく／サブスキル・食材・げんき・スキル・料理・7日間計算の優劣ではない。元のSTEP2計算結果が変更後も残る場合は「変更前の結果」の警告。適用後は既存の「7日間を試算する」で1案ずつ評価。
- イベント画面に**未保存の編集**がある場合は候補生成を拒否。候補生成後に手持ち・睡眠5匹・フィールドが変化したら古い候補の適用を拒否し、再生成を案内。適用は確認ダイアログを通し、手動の朝昼夜編成だけを保存。既存16列CSV・JSON・観測証拠・睡眠・STEP2モデルに変更なし。
- 配信用root/indexとdist/indexの両方に`step3.js`を追加。UI仮想DOMの候補表示/適用・古い候補拒否テストと、独立S3-Aテストを追加。

## 実証の限界

STEP2独立ゲーム観測0週、完全混成0/4、外部順位0/5、限定B10/14は不変。S3-Aの候補を作れることは、週間の最適順位、実ゲームのスキル抽選分布、正式なイベント補正を検証したことを意味しない。Android Chromeでの**STEP3 v0.3.0**実機動作は別途確認が必要。
