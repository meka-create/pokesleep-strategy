# STEP 2 M1：食材ゲット系の抽選対象未設定と観測ゲート（v0.2.53 / 2026-10-20）

## 確認した問題と限界

週間エンジンは `Ingredient Magnet S`、`Ingredient Magnet S (Plus)`、`Ingredient Magnet S (Present)`、`Cooking Assist S (Bulk Up)` の抽選先が `magnetIngredients=[]` の場合、期待発動による食材を `unassignedMagnet` に記録するが共有食材在庫には加算しない。

M1観測の従来の既知未対応判定はこの設定不足を含まず、食材生産・料理が実ゲームと異なり得ることを比較保留へ反映していなかった。これはユーザーの週まとめデータで検証した誤差ではなく、**一次コードの入力・計上経路を照合して見つけた証拠上の抜け**。

## v0.2.53の限定修正

- 計算スキル種の判定を `src/simulator.js` の既存 `INGREDIENT_MAGNET` キー集合から共通公開して参照。判定用の別スキル名リストを作らない。
- `src/observation.js` で、記録入力の朝昼夜・睡眠のいずれかに該当スキルを持つポケモンが含まれ、かつ抽選対象食材が未設定の場合に限って `knownModelLimitations` に保留理由を加える。
- ボックス外/編成外の該当種、抽選対象設定済み、無関係なスキルは誤判定しない。
- 保存直後のM1プレビュー、保存済みJSONのブラウザー再比較、CLIで同じ判定を使用。新しいJSONフィールドは追加しない。旧観測JSONにも記録された編成と設定から判定可能。

## 計算への影響と証拠

- 週間シミュレーターの計算分岐・エナジー・スキル発動回数・料理在庫・ゲーム確率は変更しない。
- `docs/STEP2_M1_BASELINE_V0230_20261017.json`、元R01〜R05、16列CSV、既存保存、睡眠5匹固定、週境界は不変更。
