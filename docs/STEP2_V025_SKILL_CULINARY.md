# STEP 2 v0.2.5 — 食材ゲット・鍋拡張の連続モデル

更新：2026-10-16

## 変更内容
- メインスキルの追加部分対応5種類：食材ゲットS / プラス(食材ゲットS) / プレゼント(食材ゲットS) / 料理パワーアップS / マイナス(料理パワーアップS)。
- 食材ゲット系のランダム食材数のレベル別表は pokesleep-tool の `src/util/MainSkill.ts` に基づく。
- **発見済み食材リストはボックスCSVから確定できない**。試算画面に19食材の選択欄を追加し、明示された食材集合への一様期待値配分として試算。候補未設定時は効果量を `unassignedMagnet` に隔離し、料理に使える食材へ割り当てない。
- 食材ゲットによる増分は食材バッグの容量制約に従い、獲得食材・食材在庫・料理成立判定に連動。食材の端数や抽選の同時到着は簡略化している。
- 料理パワーアップS／マイナスは発動期待値を次回料理の鍋容量増加として蓄積。上限+200。成功した料理で消費し、料理不成立時には繰り越す。
- 容量順序：`ROUND((通常鍋容量 × (日曜なら2、平日なら1) + スキル増分) × (いいキャンプチケットありなら1.5))`。根拠 https://wiki.pokesleep.com/en/pot と https://www.pokemonsleep.net/ のゲーム仕様。
- 78レシピの必要食材量と鍋容量を比較し、作れる料理のみ計上する。**余剰食材の投入・他レシピへの切替はまだ計算しない**ため、スキルによる容量アップが常に高エナジーを生むわけではない。
- 既存の固定睡眠5匹、2～3時間回収、ユーザー指定のメインスキル除外7種類を維持。
- 設定`magnetIngredients`を保存形式v1に追加し、旧JSONバックアップは`[]`として読み込む。

## 今回も未対応
- **プラス**の条件付き指定食材増分、**マイナス**の条件付きげんき回復、**プレゼント**のアメ獲得。
- 食材ゲットのランダム抽選の実分布・抽選単位、解放済み食材の自動取得、イベントの食材補正。
- 料理自動選択、余剰食材の自動投入、料理大成功・料理チャンスS、食材バッグの実整数状態。
- スキル発動時刻・確率の精密再現、前週からの鍋スキル蓄積や個体の持ち越し。

これらの未対応範囲のまま**STEP 2計算精度ゲートを合格扱いしない**。実装済みと言うときも「基本効果を部分対応」と明記する。

## 検証
- 旧CSV／バックアップと既存の除外7スキルの回帰チェックを維持。
- 食材ゲットの候補未設定時の非加算、候補設定時の対象食材配分、プラス・プレゼントの基本部分、無効な食材候補の拒否、鍋容量上限+200、日曜・キャンプ補正、料理成立比較をテスト。
- DOM互換UI起動テストに「発見済み食材19チェックボックスと保存」を追加。
- GitHub ActionsのNode実行結果と、実ブラウザ／Android Chromeでのv0.2.5実機確認は別途必要。
