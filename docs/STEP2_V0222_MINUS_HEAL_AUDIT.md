# STEP 2 v0.2.22 — マイナス追加回復の確率分布・上限監査

日付：2026-10-17（JST）。**STEP2の精度ゲート：HOLD。STEP3未着手。**

## 不一致の原因と改善

v0.2.21では「マイナス (料理パワーアップS)」の条件付き追加げんき回復を5匹への平均回復とした。旧計算式は「単発回復を上限150で切り詰めた量 × 発動期待回数 /5」。ストック2回が抽選される場合、**同じポケモンが2回とも選ばれて150上限に達する確率**を考慮しておらず、受け手のげんきが高いと期待回復量を過大に計上する。

`uniformExpectedHealFromStock(current,amount,dist,teamSize)` を新設して、スキルストックの0/1/2回分布と、各発動でランダム対象が独立に選択される二項確率 `Binomial(activationCount,1/teamSize)` を結合した期待値を計算する。各回の被選択回数のエナジー増加を150まで切り詰め、**切り詰め後に期待値**を取る。

このモデルは、連続発動時に対象が独立均等抽選されるという近似に依拠する。実ゲームの確率テーブル・発動時刻、発動回数とポケモン所持数の厳密な結合には踏み込まない。

## 独立に検算できるケース

1. 現在げんき140、単発回復8、発動2回、対象5匹均等：対象が0回64%、1回32%、2回4%。期待回復 `0.32*8+0.04*10=2.96`、最終げんき142.96。旧式は143.2と過大。
2. 発動1回、げんき149、回復8、5匹均等：得られるげんきの期待値は0.2、最終149.2。
3. 発動回数分布 `[0.2,0.3,0.5]`、げんき140、回復8、5匹均等：期待回復 `0.3*0.2*8+0.5*(0.32*8+0.04*10)=1.96`、最終141.96。
4. 回復の上限に到達しない場面では、元の単純平均式と厳密に一致（後方互換）。
5. 確率合計が1でない不正状態や過大げんき・マイナス回復値は拒否。

## 対象外と引継ぎ

- 変更対象は **マイナスの条件付きげんき回復**のみ。料理鍋効果・スキル発動0/1/2ストック・ユーザー指定除外7スキルは従来どおり。
- 他のランダム回復系（例：げんきエールの最低げんき優先、いやしのはどう）には今回のランダム対象モデルをそのまま流用しない。
- げんき150上限での二重抽選、平均げんきの非線形性、5匹の対象選択を5件の独立数値テストで検証。CIの実際のNode.js22ログを確認するまでPASSを宣言しない。
