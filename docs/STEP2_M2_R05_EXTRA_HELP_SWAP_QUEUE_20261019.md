# STEP 2 M2/R05 — 追加おてつだいの交代時未回収キュー診断

作成：2026-10-19 / v0.2.43 / **M2 PARTIAL・STEP2精度HOLD・STEP3未着手**

## 狙い

R05「ヒーラー固定 vs 朝昼夜で役割を入れ替える」の比較では、追加おてつだいの**生成数**と実際の**回収計上数**は別になる。現行 `simulate` の `collect` は通常所持品を受領・スキル発動後、`help(..., forcedHelps)` が追加おてつだいの成果を専用 `extraPocket` に積む。その直後のチーム交代では `clearDepartingPockets` が離脱者の追加所持品をクリアし、受領前の成果は週次のきのみ・食材に入らない。

従来、`extraHelps` は生成されたおてつだい回数を示すだけで、離脱により受領されない追加所持アイテム個数と発生頻度は表示しなかった。この実装上の不透明さを解消する。

## 追加した計測

- `uncollectedExtraHelpItemsAtSwap`：**離脱時に追加ポケットから消去される所持アイテムの期待個数**。確率モデルの端数あり。エナジー単位ではない。
- `uncollectedExtraHelpSwaps`：消去対象が正のチーム交代の回数。離脱ポケモンの頭数とは異なる。
- `pendingExtraHelpItems`：翌月曜04:00に追加ポケットに残っており、前週に計上されない追加所持アイテムの期待個数。上記の交代時除外量と混同しない。
- 該当時は結果の注意欄に、R05型の順位を未検証とする理由を表示。

これらの計測は**既存のエナジー・料理・スキル・キュー破棄ロジックを変更しない**。未回収品を回収済みと仮定することも、ゲーム側の損失率を推定することもしない。

## 独立性とテスト

1. 人工の専用キュー3名：離脱2名の `used=3+2.5=5.5`、きのみ `2+1=3`、食材 `1+1.5=2.5` を別算し、残留1名は保持されることを照合。
2. 7日間の2編成：追加おてつだい系スキルを持つ5匹を朝だけ配置し昼に全員交代するケースと、同じ5匹固定のケースを試算。前者で交代時の未回収キュー期待個数と交代回数が正、後者でゼロ、週内の3系統エナジー合算が総計と一致することを検証。
3. 04:00週境界：追加ポケットの残余期待個数が有限・非負で、存在する場合に注意欄で未回収として説明されることを検証。

**階級：C（既存エンジンから得た状態の可視化）**、人工キュー単体の加算は独立した算数検算。追加おてつだいの実ゲーム受領規則、交代前に発動直後の成果を再回収可能か、ゲーム内キュー持越し仕様、週次エナジーの精度をB/Aとして検証したものではない。

## 残る課題

- 固定編成の比較に対する離脱時の回収可否を、ユーザー実機または一次仕様で確認する。
- 既存のR05順位は `UNVERIFIED_RANKING` のまま。R01〜R04も独立した実ゲーム順位証拠なし。
- M01〜M04の混成7日間、E4ヒーラーのスキル率とげんきタイマー相関は依然外部未検証。
- 確認できない仕様を仮定して `extraPocket` を自動回収したり、初期ベンチマークやR05数値を上書きしたりしない。
