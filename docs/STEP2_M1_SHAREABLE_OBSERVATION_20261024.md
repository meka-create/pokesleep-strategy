# STEP 2 M1 — 観測JSONを限定開示して再計算できる共有版（v0.2.74 / 2026-10-24）

## 対象の実際の不足

Issue #68のM1完了条件は「保存観測JSON（個人情報を除く）のブラウザ/CLI照合」。v0.2.73の実測JSONは実際に再計算できるが、元の`input.box`のニックネーム・内部ID、スクリーンショットのファイル名、イベント補正の自由記述などがそのまま含まれ、データ共有時に不要な情報を開示してしまう。今回の修正は**観測データを実際に取得したという主張ではなく、取得したデータを最小限の開示で共有するための導線**。

## 追加機能

- 実測観測JSONファイルを選ぶ「週間実測JSONから共有用コピーを作成」をM1画面に追加（手動・任意）。ファイルの外部送信はしない。
- `src/observation.js` に `shareObservation(report, simulate)` を追加。入力ファイルに`reviewImportedReport`の厳格検証と**元のボックスで実際の週間再計算**を通し、共有用を生成した後も共有用で再計算して、`total/berries/skills/cooking`と観測`status`、制限件数、未確認条件件数が維持されない場合には出力を拒否。
- 元の`id`はソート後の順序で`P00001`等の仮名にし、朝昼夜・睡眠5匹の参照を同時に置換。元ボックスの配列順序は維持し、同一ボックスの行順を変えても同じ参照IDにする。ニックネーム、メインスキルの個体側自由記述、拡張フィールド、スクリーンショット識別子はコピーしない。
- エネルギー計算に使う種族、レベル、スキルレベル、開放食材、サブスキル、せいかく、睡眠時間、フィールド、FB、料理・食材・回収・キャンプ条件、同一5匹編成、観測した実測値、記録時の版・診断カウンター、確認フラグは保持。自由記述のイベント補正は、内容を伏せても「未モデル化の補正があり得る」という比較保留を消さないため、空でなければ固定文字列へ置換。
- 共有用は従来と同じ`step2-m1-weekly-observation-v1`で、既存のブラウザ比較／`npm run m1:observe -- file.json`／R02型比較へそのまま渡せる。原ファイル・ブラウザのボックス／保存値は変更しない。

## プライバシーに関する重要な限界

**匿名化の保証ではない。** 種族・レベル・能力・編成構成・週日付・ゲーム内の週実績が残るため、知っている人が別の情報と照合すると個体や遊び方が推測される可能性がある。原画面と共有用JSONの一致を自動で保証しない。ユーザーは共有前にファイル内容を確認する。元のスクリーンショット識別子は消えるので、第三者照合のための原本対応はユーザー側で別途保持する。
