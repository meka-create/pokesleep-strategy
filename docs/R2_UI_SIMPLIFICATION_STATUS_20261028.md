# フェーズR2 初回UI簡素化 — v0.5.5（2026-10-28）

## 目的・基準

- 基準：W4正式承認済みv0.5.4、main `900961c6927ab4675f1f8ed990eb6ebd7f4b3c84`。
- 優先：ユーザーが最も重視する「月～日・朝昼夜21枠の自動提案／任意の睡眠7晩提案」を最初に見せる。内部の複雑な計算は維持し、通常表示の説明・重複操作を減らす。
- W4承認内容を維持：睡眠自動提案は初期OFF、OFF時は7晩個別編集・全晩コピー可能、ON時だけ夜別自動探索。夜間完全放置、月曜04:00境界、CSV16列、旧JSON v1は変更しない。

## 今回の変更（ユーザー導線のみ）

1. メイン5タブを3タブ「作戦／ボックス／準備」と右端の設定アイコンに縮約。作戦タブ内にイベント条件と週間編成を集約。
2. 大きなヒーロー・開発STEP表示・フッターの開発状況・重複する説明文を撤去。
3. イベント設定は現在のフィールドを示す折りたたみ形式へ変更。きのみ自由入力・補正メモは保存互換のためDOMに残すが、計算非反映なので通常表示から隠す。
4. 週間自動提案を上部の唯一の主ボタンへ。反映前のプレビュー、採用ボタンを直下に配置。日別編成は月曜のみ展開状態で他の曜日を折りたたみ、必要な曜日を開いて確認。手動編集も折りたたみ式。
5. 旧A/B/C候補のUI、週の実測記録・共有UIは `hidden` で通常表示から除外。コード・エビデンス・テストは保持（本格的な撤去はR3）。旧固定3編成・詳細計算条件は折りたたみ内に維持。
6. 試算結果は参考エナジーを中心に表示し、料理・食材詳細と未対応条件は必要時に開く。エラーや保存失敗の警告は引き続き常時表示。
7. 準備週の詳細参考試算・2方針比較は折りたたみ。料理必要数の基本入力・計算は残す。

## 変更していないもの

- `src/simulator.js`、`src/week-optimizer.js`、`src/storage.js`、`src/step3.js`、`src/step4.js`、`src/observation.js` の計算式・保存方式。
- 検証用のコードとJSON操作。通常UIから隠すだけであり、削除やデータの初期化はしない。
- メイン週次探索上限12回、結果が参考値であること、保存失敗時のロールバックと旧提案の失効。

## 次の改修課題

1. R2追加：日別編集のスマホ導線の磨き込み、より少ない操作での曜日・時間帯の変更、初回セットアップ案内の簡素化。
2. R3：旧STEP3候補・実測記録をブラウザバンドルから外し、独立テスト・開発工具に分離。旧3枠保存互換を維持しつつUIの重複導線を削除。
3. R3以降：準備計画の30%／90%暫定方針の置換方式を確定してからコード整理する。2週未実装の入力やイベント補正は機能対応まで積極的に表示しない。

## 受入・品質ゲート

- 自動テスト：`npm run check`、R2静的導線テスト、生成HTML 2コピーの完全一致を確認する。
- スマホUI：Android Chromeで作戦・ボックス・準備・設定が開けること、イベント条件の編集保存、週間提案の生成／採用、7日別編成の開閉・手動変更、手動睡眠7晩の保持、再読み込み・バックアップを確認する。
- UI専用Playwrightの手動実行はローカル環境にChromiumがなく、インストール先からの取得ファイルが不完全だったため実行できていない。これをPASSとは扱わない。Android Chrome実機受入で補う。
- 実ゲーム計算精度／数学的最適性は従来どおりHOLD。R2自動回帰PASSは実ゲーム精度を証明しない。
