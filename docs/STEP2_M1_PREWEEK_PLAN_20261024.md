# STEP 2 / M1 事前予測の固定・観測週日時の判定（v0.2.72、2026-10-24）

## 再現した証拠管理の問題

v0.2.71の観測UIは、ゲーム週間まとめを見た**後で**7日試算を実行し、その場の計算設定と実測値を1つのJSONに保存できた。JSONには `capture.capturedAt` が存在したが、週の境界（月曜04:00 JST）との前後関係を検査・表示しなかった。事後的に設定を合わせた数字が「事前固定の予測」と混同され得る。さらに週開始前に試算しても、そのスナップショットを独立ファイルとして書き出して週終了後に取り込む操作がなかった。

これは**ゲーム上のエナジー式の誤りではなく、M1実測収集における予測出典・再現性の欠落**である。実ゲーム独立証拠0週を水増ししない。

## 修正

1. `makePlan(snapshot,mondayDate)` で、実際の月曜日・日本時間04:00より前の試算だけを `step2-m1-weekly-plan-v1` 形式で出力する。試算時点の `input`、4つの予測エナジー、あれば5つの診断値、アプリ版とISO試算時刻を固定。ニックネーム等を含むためファイルはユーザー端末内で扱い、外部送信なし。
2. `snapshotFromPlan(plan)` で、スキーマ、週、フィールド、編成5匹、ボックス個体ID・数値、試算内訳、日時と記録メタデータを検査して読み込む。**端末のボックス・保存状態は変更しない**。実測の曜日を後で変更すると拒否する。
3. 観測フォームを週間結果カードの外に移した。ページを閉じた後でも「事前予測JSONを読み込む」→観測週の日付を復元→手動で実ゲーム週まとめと確認フラグを入力→従来の観測JSONを出力できる。新しい観測ファイルのスキーマ `step2-m1-weekly-observation-v1` と従来CLI・複数週再読込は維持。
4. `forecastTiming` が月曜04:00 JST〜次月曜04:00 JSTを境界として `PRE_WEEK` / `DURING_WEEK` / `AFTER_WEEK` を返す。後2者はブラウザのプレビュー・再読込・CLIで同じ`modelLimitations`を付け、`CONFOUNDED_OBSERVATION`にする。
5. **端末時計と編集可能なJSONは第三者による時刻証明ではない**。PRE_WEEKでも `independentlyVerified=false`、単一観測の `accuracyGate=HOLD` と `rankOrAccuracyValidated=false` を維持。保存したという事実だけでゲーム予測の独立A級証拠や順位を合格にしない。

## 推奨する採取手順

- 対象週の開始前：7日試算→観測欄の対象月曜日→「対象週の事前予測JSONを保存」→別途、ゲームの実際の編成・初期値・回収時刻・週境界条件を記録。
- 対象週が終了してから：保存済み事前予測JSONを読み込む→ゲーム内の週まとめ・スクショ識別子・確認できた条件のみ手入力→「週間実測と試算条件をJSONで保存」→必要に応じ4週比較・CLI `npm run m1:observe`。事後に計算し直した結果で事前の予測を置き換えない。
- 時計・入力内容の改変やゲーム実績の真正性を自動検証できない。スクショの証拠原本は人手で別途管理し、未確認条件は必ず保留。

## 回帰

`tests/step2-m1-preweek-plan.test.cjs` は境界の前・ちょうど04:00・週末の前後、スナップショット深いコピー、ファイル復元、別週の誤割当拒否、事後試算の比較保留、スキーマ・編成・フィールド・記録時刻改変の拒否を確認する。

変更対象はM1観測・見せ方・証拠管理のみ。週間シミュレーター、マスター、睡眠固定、CSV16列、M1凍結基準 `docs/STEP2_M1_BASELINE_V0230_20261017.json` は変更しない。**限定B 10/14、混成完全週0/4、外部順位0/5、実ゲーム週0。M0 DONE、M1/M2/M3 PARTIAL、M4 NOT STARTED、STEP2精度HOLD・STEP3未着手。**
