# STEP 2 M1 — 実ゲーム「1週間のまとめ」観測票と比較手順

更新：2026-10-18。**M1 PARTIAL／STEP2精度HOLD／STEP3未着手**。

## 今回、実データから利用できるもの

[ポケモンスリープ攻略・検証Wiki：一週間の流れ](https://wikiwiki.jp/poke_sleep/一週間の流れ)によると、**月曜04:00**の週切り替え後に表示される「1週間のまとめ」**最初の画面**には、最終「総エナジー」「きのみでのエナジー」「料理でのエナジー」が表示される。この画面は**後から再表示できない**と記載されているため、比較する週は初回にスクリーンショットを保存する。

**注意すべき分類：** このWikiには、ゲームの「きのみでのエナジー」に**エナジーチャージのエナジーが含まれる**と明記されている。M1でゲームの「きのみ欄」と、シミュレーターの `berries` だけを比較すると、スキル分を架空の誤差と判定してしまう。今回の比較ツールは**モデル `berries + skills` を暫定的な対応区分**とし、料理欄はモデル `cooking` と比較する。すべての特殊スキル／イベント効果が必ずこの分類に収まると保証したわけではない。ゲーム内の2欄合計と総エナジーが異なる場合は、差を隠さず表示する。

## 実測取得の最低限の記録

- 月曜04:00の週まとめ**最初の画面のスクリーンショット**：総エナジー／きのみ欄／料理欄の3値。再表示できないため画面を閉じる前に保存する。
- 対象週の月曜の日付、フィールド、週の料理カテゴリ、フィールドボーナス、好みのきのみ。特別イベント・EX効果・いいキャンプチケット・アイテムの利用があった場合はその条件。
- 同じ7日の朝7:30～12:00、昼12:00～18:00、夜18:00～0:00と固定睡眠0:00～7:30の**実際に採用した5匹**。途中変更した場合、時刻も記録。
- 料理のレシピ・回数・大成功・追加食材（分かる範囲）。寝た時間／睡眠スコア／回収時刻が通常設定から違った場合も記録。
- ポケスリ作戦室の個体ボックスと設定を再現できる**JSONバックアップ**があれば保管。個体データなどを公開したくなければ無理に公開しない。
- 比較の際、ユーザー報告の写真や数値が**実際に画像と一致したかの確認**は別途必要。JSONの登録だけで検証済みA級にはしない。

## プログラムに入力する方法（開発用）

`docs/STEP2_M1_WEEKLY_OBSERVATION_TEMPLATE.json` は**空の実測テンプレート**。数値の `null` は未入力であり、架空のゲーム実測値を入れていない。

1. テンプレートを別名で保存する。実測した月曜日を `week.mondayDate: "YYYY-MM-DD"`（有効な月曜日）で指定。
2. 週まとめの3値を `observed.total`、`observed.berryAndStrengthSkill`（**ゲーム画面の「きのみでのエナジー」の数値をそのまま**）、`observed.cooking` に記入。
3. `input` はポケスリ作戦室エンジンの7日シミュレーション入力形式 `{box,teams,options}`。ボックスのJSONバックアップをそのまま代入すれば必ず動くという意味ではない。必要なら別途変換する。
4. `week.field` と `input.options.map` を一致させる。確認済み項目のみ `provenance.noUnmodeledEvents`、`sameCollectionSchedule`、`noUntrackedItems`、`startStrengthVerified`、`weekBoundaryReconciled` を**JSONの真偽値** `true` にする。未確認は `false`（古いテンプレートでキーが欠けた場合も未確認）。文字列の `"false"` / `"true"` は入力エラーにする。
   - `weekBoundaryReconciled` は実ゲームの**月曜04:00〜07:30**の取得・操作・エナジーと、本モデルの**月曜07:30開始**の対象区間差を、同じ週の比較でどう扱うか個別に照合できた場合のみ `true`。単に同じ月曜の日付を指定しただけでは `true` にしない。
5. `npm run m1:observe -- path/to/filled-real-week.json` を実行。総エナジー・「きのみ+スキル」・料理の**観測値−モデル値**と、未確認条件をJSONで出力する。

**これは入力した実測値の真偽を自動検証する仕組みではない。** 1週間は確率変動が大きいため、実際の観測値と期待値の差分が出ても、即座にP0・P1・誤差率・編成順位の確定判定は行わない。連続した同条件の測定や、独立参照実装などと合わせて次段階で評価する。

## 守るべき精度・プライバシーの境界

- 本ツールは**ゲームへの接続、画面取得、スクリーンショットの自動検証を行わない**。すべてユーザーまたは検証担当が自発的に提供した観測値を計算する。
- `rankOrAccuracyValidated=false`、`accuracyGate=HOLD`、`step3=NOT_STARTED` は観測した数字が完全一致しても維持する。
- 「ゲーム内きのみ欄にメインスキルによる直接エナジーが含まれる」は公式APIの細かな分類仕様ではなく上記の公開Wiki記述に基づく。分類の不整合は理由を確認してから修正する。
- 個体のニックネーム・睡眠記録・その他の私的なスクリーンショットは公開リポジトリへ無断でコミットしない。実データが無い間に**架空のサンプル値をA級観測結果として追加しない**。
- 現行v0.2.30の7日試算は**月曜07:30～翌月曜04:00**。週まとめは月曜04:00更新のため、週の始まり04:00～07:30に収集や特殊な操作があると、モデルとの直接比較は不適切。実ゲームとの時間範囲の違いを必ず記録する。
