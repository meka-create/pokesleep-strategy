# STEP 2 M1 — R02 ヒーラー1匹対2匹の2週観測スクリーニング（v0.2.55）

日付：2026-10-20

## 課題と狙い

M1の代表5比較のうちR02は「日中ヒーラー1匹対2匹」で、現行週次モデルのスキル率0.75倍／1倍に対する順位の符号が反転する。
これは既存のC級モデル感度であり、ゲームの正しい順位や確率の証拠ではない。従来の観測JSONの複数週読み込みは、
完全に同じ試算入力かどうかを比較できるが、**1匹だけヒーラーへ入れ替えた対照2週を識別しない**。
そこで実ゲームの記録が提供された際、R02の仮説を確認可能なペアへ仕分ける。

## v0.2.55で追加した判定

ブラウザーで同時に選んだ2つの観測JSONを既存の `reviewImportedReports` に通し、付加情報 `r02TwoWeekScreen` を返す。
CLI `npm run m1:r02-two-week -- week_one.json week_two.json` でも共通の `PokeObservation` 判定を使用する。

**参考差分を表示できる必要条件：**

- 週開始月曜日が異なり、観測2件の週まとめエナジーとゲーム上の2欄が整合する。
- 2週のボックス内容・個体のレベル・食材・サブスキル等、モデルへの全options、固定睡眠5匹の配列がそれぞれ一致する。
- 各週の朝・昼・夜は同じ固定5匹。1週の全員回復メインスキル持ちは1匹、他週は2匹。日中5匹の共通部分はちょうど4匹。
- 5つの観測確認フラグがすべてtrue。保存時の試算値と現行再試算が一致。旧式診断の不足・診断ドリフトがない。
- 比較不能な食材・料理・イベント・未対応効果など、**R02特有の回復時刻・10分タイマー・150上限以外**の未検証条件がない。

これらのいずれかが成立しない場合、`NON_COMPARABLE` と具体的な理由を返し、**2週のエナジー差自体を隠す**。
条件一致でも `DESCRIPTIVE_ONLY` であり、2匹週−1匹週のユーザー入力合計差／同一モデル期待値差／その隔たりを参考情報として表示する。
逆順でファイルを指定しても符号規約を維持する。

## 何を証明しないか

- 観測JSONの出典は手動入力で、スクリーンショットの内容・入力者の確認事項の真正性をソフトが検証したわけではない。
- 実験条件をモデル入力で揃えても、**異なる2週でゲームのイベント・天候・実際の操作・スキル抽選・所持数や初期内部状態が一致するとは限らない**。
- 一つの確率試行ずつを並べた2週の差から期待値の正確性や確率的な勝率は求めない。 `observedSign` と `modelSign` が一致しても、R02順位の合格とはしない。
- `reviewImportedReports` の `rankOrAccuracyValidated`、個別の `accuracyGate` と本スクリーニングの `accuracyGate` は常に `false/HOLD`。
- M1主14条件の限定B照合 **10/14のまま**、混成4件未検証、R01〜R05のゲーム順位0/5、実際のゲーム週観測0件。

## v0.2.56 追加監査：警告分類の完全一致

R02/E4だけの制限を例外とする条件に文字列の部分一致を使うと、未知の種族名が「R02型」や「げんき回復時の150上限」を含むだけで、**未登録種族をモデルが計算していないという本来の比較保留**を誤って許可する余地がある。既知の3つのR02/E4警告の全文一致に変更し、入力した未知種族名による比較通過を防止。ゲーム順位や確率の検証済み項目は増加しない。
