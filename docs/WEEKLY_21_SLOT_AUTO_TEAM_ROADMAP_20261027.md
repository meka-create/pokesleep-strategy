# 週間21枠・自動パーティ提案 — 最優先軌道修正ロードマップ（2026-10-27）

## 位置づけ・ユーザーの原要求

ユーザーの2026-10-27の明示フィードバック：

> 私の希望と一番違う点は、7日間のパーティが常時同じ構成で試算されてしまっていること。月～日曜日の朝時間、昼時間、夜時間のパーティをツールに自動提案してもらうことが一週間のエナジーを多く稼ぐうえで必要となる。

**最優先で実現する価値**：既存のボックスから月〜日各日の朝・昼・夜の **21枠×各5匹** をツール側で自動提案し、日をまたぐげんき・所持・食材・料理・スキルを一貫して計算した **週間エナジー** を評価する。「一日分の朝昼夜を7回繰り返す参考編成」は比較基準として残せるが、完成仕様の代用にはしない。

現行 STEP1〜STEP4 はユーザー承認済み（STEP4 v0.4.5は条件付き機能完成）とし、過去の承認を取り消したとは扱わない。ただしこの核心機能が未実装であることを明示し、**従来の STEP5（イベント補正・ランダム・2週連動）の実装より先に、独立した最優先フェーズ W として開発する**。実装フェーズ W の詳細と開始はユーザーの指示に従う。STEP5は未着手。実ゲーム精度・編成最適順位の実証はHOLD。

## 既存実装と不足を一次コードで確認

- `src/step3.js` の `createCandidates` は `{morning,noon,evening}` だけを作り、A/B/C等の高々6候補を比較する。日付次元がない。
- `src/simulator.js` の `simulate(input)` は `teams.morning/noon/evening/sleep` を受け付け、`for (d=0;d<7;d++)` の内部で毎日同じ `teams[key]` を参照する。異なる曜日・スロット間の最適化はできない。
- `src/app.js` の操作・描画・STEP3候補反映も、3枠の固定 `state.simulation.teams` を使う。
- STEP4の2方針（バッグ30%／90%）や食材一致度による参考案は週間21枠のエナジー最適化ではなく、この不足を解決しない。

## 固定仕様（改変禁止）

- 1日の日中：朝 07:30–12:00、昼 12:00–18:00、夜 18:00–00:00。昼・夜の交代は**任意**で、同じ5匹の継続も可能。
- 睡眠 00:00–07:30は完全放置し、ユーザーが指定した睡眠パーティ5匹を**7日間固定**、最適化器の選択対象にしない。07:30は先に睡眠編成の回収、その後必要なら日中編成へ変更。
- 週の境界は月曜04:00。週次計算は月曜07:30〜翌月曜04:00で、4:00〜7:30の成果を旧週へ加算しない。最終睡眠期間は翌月曜04:00まで計上。
- 日中回収約150分（120～180分）と任意の12:00／18:00変更を尊重し、非現実的な深夜操作・時刻外交代を要求しない。
- 既存CSV16列、JSON version:1の旧バックアップ、旧3枠シミュレーター、STEP3/4の承認済み機能は維持。旧バックアップは従来の3枠を7日へ展開する互換経路で読み取る。

## 開発順（フェーズW：従来のSTEP5より優先）

### W1：曜日別21枠に対応する週次シミュレーター

1. 明示的な日別編成 `teamsByDay[0..6].morning/noon/evening`（各5個体ID）を受け付け、全枠の重複ID、未登録個体、枠不足等を厳格に検証する。別途 `teams.sleep` は固定。
2. 現行の`teams.morning/noon/evening`入力も変更せず継続して受け付け、暗黙的に7日へ展開できるようにする。旧入力に対する計算値が変わらないことを回帰確認する。
3. **げんき・スキル不発履歴・ストック・所持枠・追加おてつだい・食材バッグ・料理消費・鍋拡張等の状態を週内で連続**させ、曜日境界で勝手にリセットしない。入替時の回収・未回収・離脱効果は現行ルールに照らして扱う。
4. 毎日の回収と料理・きのみ・スキルを同一計算器で評価し、日別・合計の内訳が一致するようにする。月曜04:00の境界を守る。

### W2：21枠を**自動で探索**する編成エンジン

1. 「睡眠5固定＋ボックスの他の個体」を候補に、曜日・時間帯ごとに編成を変える案を生成する。同じ編成を7日間繰り返す案は**ベースラインの1候補**として含める。
2. 目的の第一順位は **週間エナジー計算値の最大化**。きのみだけでなく料理・食材・回復・スキル・翌日への状態持ち越しまで、W1の7日間評価を通す。簡易きのみ指標のみで最高と確定しない。
3. 全組合せの総当たりは要求しない。限定候補の生成、局所変更や時間帯ブロック変更、週全体の再評価、重複試算キャッシュ、計算上限・停止条件を備えた **有界探索** とする。前日からの連続性と翌日への効果のため、21枠を個別独立で貪欲に決めない。
4. 同じ条件の固定3枠ベースラインと比較し、改善した週間エナジー・日別内訳・変更回数・既知の不確実性を表示。**算出モデル上の探索範囲内での最良案**と明示し、全空間の数学的最適解や実ゲーム最適解とは呼ばない。
5. 入替削減は**第二目的**。僅差で操作回数を減らす選択肢は別案として提示し、ユーザーの知らないうちに週間エナジーを大きく犠牲にした案を「最大」と呼ばない。朝昼夜が同じでもその日の計算により選択された結果なら可。

### W3：7日×3枠の提案・反映・調整UI

1. 月〜日の7行（または1日ごとの折りたたみ）×朝／昼／夜の5匹を表示。各枠の入替操作、編成継続、曜日別の予想エナジーと週間合計を視認できること。スマホ縦画面で操作可能。
2. 「週間自動提案」「週の提案を試算」「固定3枠案と比較」を基本導線にする。時間帯ごとの交代必要数、7:30の回収後切替、12:00／18:00の任意変更を一覧化する。
3. 提案は初期状態で**保存済み編成を変更しないプレビュー**。明示的な反映操作で曜日別計画のみ保存し、固定睡眠5匹や現行3枠設定、イベント設定を自動上書きしない。条件変更時は旧提案を破棄/失効表示。
4. 日別の手動調整、当日の進捗に合わせた残日程の再提案は拡張対象。最低限、保存・復元/リロードと21枠の手動編集を扱う。

### W4：受入・安全性・次のイベント機能への接続

- W1互換：旧固定3枠を7日に展開して旧結果と一致、7日すべて異なる編成も評価可能、曜日を入れ替えると結果が適切に変わる。
- W2有用性：候補内に固定3枠ベースラインを含め、同一条件の同じ計算器による比較で週間エナジー改善または同点を示す（探索上限や未対応条件は明示）。
- W3実機：Android Chromeで21枠表示・提案・曜日別編集・保存/復元・睡眠固定・交代確認が正常。実機未確認項目はPASSにしない。
- 回帰：既存STEP1～4、CSV16列、旧バックアップ、7日計算結果、月曜04:00境界、生成HTML一致を確認。
- 精度：独立実ゲーム照合が不足する限り「実ゲームでの最適」と断言しない。週間数値・相対順位のHOLDは保持。
- フェーズWの実装→自動検証→公開→ユーザー厳密監査→**明示承認**を完了してから既存STEP5へ進む。
