## 差異を確認した一次コード

- [nitoyon/pokesleep-tool — EnergizingCheerHealPulse.ts](https://github.com/nitoyon/pokesleep-tool/blob/main/src/util/Team/Skill/EnergizingCheerHealPulse.ts) は `addEnergizingCheer` を呼んで対象1匹を決め、**その1匹をメンバー配列から除外**して、残り4匹のプールで再度呼び出す。さらにそれぞれへスキルLvの追加おてつだいを割り当てる。特定のラティアス／ラティオス関連スキルを持つ対象がいると追加おてつだいが増える特例は元のモデルのまま。
- [nitoyon/pokesleep-tool — EnergizingCheer.ts](https://github.com/nitoyon/pokesleep-tool/blob/main/src/util/Team/Skill/EnergizingCheer.ts) の `addEnergizingCheer` は **65%確率でげんき最低の対象（同率なら均等）、35%確率で全員から均等**。抽選時点の各メンバーげんきを用い、その対象へ回復効果を適用してから次の抽選が始まる。

したがって1発動に限っても、以前の作戦室の「5匹すべてに2/5回の期待対象回数を割り当てる」方式は、げんき差がある場合、独立参照の抽選と合致しない。

## 修正したモデル

- 現在時点で与えられた5匹のげんきについて、まず65/35で対象1匹目を選択し、対象の回復（せいかく補正および150上限を適用）を反映。その後、残り4匹について65/35を再計算し、2匹目に同じ回復を反映する。
- 全 **5×4=20通りの順序付き枝**を合計し、1匹あたりの「対象として選ばれた期待回数」（合計2回）と、1回発動後のげんき期待値を得る。抽選枝ごとに個体重複なし・選択確率質量1を確認する。
- 単体試験では**独立した算術関数**で20枝を再列挙し、初期げんきの偏り、げんき最低同率、せいかく補正、上限150、全員150、回復0などの全枝平均と照合する。不正な編成・回復量・げんき・性格補正値の入力は拒否する。
- 週間エンジンでの既存の期待スキル発動回数に、この1回あたりの対象選択・回復・追加おてつだい期待値を掛ける。**実ゲームの発動時刻・おてつだい完了の時刻と次のスキル抽選・所持数・げんきタイマーの結合分布までは再現しない**。期待回復のタイマーリセットによる非線形差も独立検証前のまま。
