# STEP 2 M2 — 満杯後4回のスキル抽選キュー（2026-10-23 / v0.2.68）

## 背景：週間計算本体と外部実測知見の不一致

従来の `integerPocketTransitions` / `integerFoodPocketTransitions` は所持枠が満杯の瞬間以降、完成したおてつだいのスキル抽選資格を**即0**にする。2026-10-10更新の[ポケモンスリープ攻略・検証Wiki『メインスキル』](https://wikiwiki.jp/poke_sleep/メインスキル)と[『おてつだい』](https://wikiwiki.jp/poke_sleep/おてつだい)は、いつのまに育成へ移った後も**最大4回**のキュー内おてつだいでスキルが発生する可能性を記している。[キュー機構の検証](https://wikiwiki.jp/poke_sleep/検証/メインスキルのクールタイム)も別記録。Game8の一般向け説明は「満杯後には抽選されない」とまとめているが、ここでは時間内の4回の残存例外に焦点を当てる。

このため、スキル率が高く睡眠中や長時間回収しないときに所持が満杯に達する個体について、従来のモデルは**キュー末尾の4回の抽選を失う**。メインスキルの待機ストック上限・ピティは従来の整数抽選状態に渡すため、通常の各スキル効果や確定済み29対象/7除外の選択は変えない。

## 変更・仮定

* `queuedFullPocketTransitions` は状態 `(occupiedSlots, postFullRollsUsed=0..4)` と各区間内の整数おてつだい回数を同時に確率遷移する。未満杯なら通常の抽選資格、満杯後は**4回まで**抽選資格、5回目以降は資格なし。満杯後も生産はきのみのいつのまに育成で、食材は加えない。
* 15分刻み/回収時刻をまたいでキューを保持し、**区間ごとに4回補充しない**。所持数の元の確率遷移・料理食材期待値・いつのまに育成のエナジー式は維持し、抽選資格の分布だけ上記のキュー付き経路で更新する。
* 通常の回収で空になるポケットは新しい4回許容の準備状態に戻す。満杯ポケットをまったく回収できなかった場合は従来の使用済み回数を保持。
* **未解決の部分回収**：満杯のまま一部だけ回収したとき、種類別食品とキュー残存履歴の全結合は週次本体にない。ここで適当な新規4回を与えると過大計上するため、満杯枝を『4回使用済み』へ保守的に再構成し、その条件で警告する。これは真の抽選率下限・週間誤差境界ではない。
* 指定4回が常に実際に有効抽選として蓄積されることを保証するのではなく、既存のスキルストック上限・不発天井が待機抽選を止める。技能発動履歴・事後スキル抽選秒の真値はユーザーの週間観測がないため検証不足。
* 通常の追加おてつだいキュー、編成交代・離脱、睡眠固定、週境界、CSV16列、観測JSON・保存形式、凍結 `docs/STEP2_M1_BASELINE_V0230_20261017.json` は不変更。

## 再現・独立小条件（B級）

完全きのみ生産・1回2個・所持上限2・スキル抽選前のストックに余裕・初期所持0。

* **10回おてつだい中の抽選資格**：1回目は所持枠を埋める通常抽選、続く2〜5回目は満杯後の4回残存抽選、6〜10回目は抽選資格なし。従来は1回、新モデルは**5回**。
* 同じ10回を2回＋8回（または任意の15分区間）に分割しても抽選資格が5回のままであり、満杯キューは一度しか消費しない。
* 所持3・1回のきのみ2/食材1の独立確率40%・2分岐について、手書き完全列挙とモデルの `P(eligibleHelpCount)` / `P(occupied,queueUsed)` の一致を検証。
* 満杯のまま無回収なら消費済みキューを保持。空にできれば新たな通常抽選から再開。部分回収で不確実な場合は追加4回を捏造しない。
* フワライド5匹の7日スモークで、合計・日別内訳・スキル期待値の有限性と保存則を維持。

## 証拠の限界・次の優先度

満杯後の短い抽選キューの存在は外部コミュニティ検証からの**局所A/B仕様根拠**だが、実ゲームで個体別に4回の頻度や停止時刻を計測できたわけではなく、**元M01〜M04の完全混成週間外部参照には当たらない**。曜日・料理・エネルギー・共有バッグ・待機ストックと4回キューの完全同時分布も未接続。人工条件だけで『4条件合格』や『R02/R05の順位確認』と判定しない。
