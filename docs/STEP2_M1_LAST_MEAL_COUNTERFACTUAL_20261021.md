# M1：最後の固定料理1食の不成立と後続きのみへの影響 — 人工7日独立時計算

作成日：2026-10-21 ／ STEP2 v0.2.58

## 根拠と狙い

v0.2.57の凍結M02/M03では、りんごカレー21食の必要数147個に対して確定初期食材140個であり、
20食は初期個数により賄えるものの、最後の1食は食材ドロップ期待値に依存している。
1食直接エナジー3,347の有無**だけ**が週間合計へ影響するとは限らない。料理回復が入れば、げんき残量・10分減少タイマー・
後続のおてつだい完了整数回数・獲得きのみエナジーが変わり得る。ここを制御可能な**人工2条件**で切り出す。

## CM04 / CM05の固定条件と操作

新条件は、旧CM01〜CM03の独立1分時計算と週間本体の双方で同じ「実現した操作列」を指定する。

- Lv50のライチュウ2匹・フシギダネ5匹から日中固定5匹、睡眠固定5匹。個体所持容量を十分大きく設定。
- りんごカレー固定（必要リンゴ7・Lv70基礎2,678）、フィールドボーナス25%。鍋容量57、バッグ容量500、いいキャンプOFF、追加食材OFF、大成功OFF。
- **全個体の食材抽選率0%・メインスキル発動率0%**。意図的な人工設定でありゲーム上の通常確率ではない。
- 睡眠スコア0、初期げんき30、起床7:30→昼12:00→夜18:00、タップ150分ごと、00:00〜07:30は非操作、次の月曜04:00で週切替。
- CM04は初期りんご**140個**、CM05は**147個**。この違い以外の入力と操作は同じ。
- CM04では日曜夜の21食目のみ料理不成立、CM05では21食とも成立。他の20食の料理・げんき回復・時刻は一致する。

一方の参照は **独立の1分時計算**で、毎分のげんき10分減少タイマー、個体別のおてつだい端数、各時点の料理成否、
回復での減少タイマー再起算、次の回収時のきのみ評価を直接積み上げる。
もう一方は本体の15分刻み7日モデル。CM04とCM05のそれぞれにおいて、
合計・きのみ・料理・食事数・食材生産ゼロ・消費数・在庫・料理時系列を照合する。
さらに**CM05−CM04の差分**を直接比較し、追加料理直接エナジー3,347と、
同じ料理による回復後のきのみ差分を別々に記録する。
