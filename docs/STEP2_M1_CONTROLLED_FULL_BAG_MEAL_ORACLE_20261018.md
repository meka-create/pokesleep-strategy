# STEP 2 M1 — バッグ満杯から料理で空きを作る7日間の独立検算（2026-10-18）

**CM03は食材率100%/0%・スキル0%の人工制御条件。実ゲームのバッグ満杯・スキル抽選やM04の精度合格ではない。STEP2 HOLD／M1 PARTIAL／STEP3未着手。**

## 既存CM01/CM02から追加した検証

[CM01/CM02](STEP2_M1_CONTROLLED_MEAL_ORACLE_20261018.md)は食材バッグ容量無制限のため、料理までの食材流れは検算できても「グローバル食材バッグが満杯」という重要な連携処理を検証できなかった。

**CM03**は、固定5匹（食材担当ライチュウ1匹・きのみ担当フシギダネ4匹、睡眠編成も同じ）、初期リンゴ7個・**共有バッグ容量7**、リンゴ7個消費するカレーを21回のタイミングで試みる。

- Lv50／まじめ／サブスキルなし／スキル発動率0%。ライチュウは食材抽選を必ずリンゴ1個にし、フシギダネは必ずきのみ1個にする（**人工的な確定抽選**）。個体所持枠は100万に拡張し、個体側のいつのまに育成を排除。
- 外部参照は、各分のおてつだいを個体ごとのリンゴ・きのみポケットに加算し、**回収操作時のみ**空いている共通バッグ枠へ整数個を移す。満杯で移せなかった食材はポケモンのポケットに残る。回収中にポケットのきのみエナジーを加算する。
- 料理時点で共通バッグのリンゴが7個あれば7個消費・料理エナジー計上・メンバーのげんき回復。空きができた後の次の実回収時刻まで、個体ポケットに残るリンゴを勝手に食材バッグへ移動させない。
- 月曜04:00で週を閉じる。日曜深夜の未回収食材は今週の在庫・料理計上から除く。
- 別実装1分時計算と本体の**きのみ・料理・合計エナジー、料理21機会の成立履歴、回収食材、消費食材、期末在庫**を独立に照合する。

`npm run m1:controlled-meals` でCM01〜CM03をまとめて出力。CM01/CM02のCI固定参照ファイルは変更せず、CM03の数値はCI実行結果が確認できてから追記・保存する。

## 証拠の境界

1. 共通バッグ満杯で食材が個体ポケットに残り、料理の実消費でバッグが空き、次のタップで回収できるという**人工的に決定的な手順**のみ検証できる。
2. ポケモン側の最大所持数超過、食材種類別の確率、食材ゲットSの待機ストック、複数個体の共有バッグ相関、実ゲームの確率抽選は**含まない**。
3. M01〜M04の元の全要素モデルは4件ともC級。5組のランキングも実ゲーム未検証。限定B級10件／未検証4件という主マトリクスの数は変えない。

この試験から不一致が見つかれば、独立時計算・本体・現行仕様を比較して修正可否を決める。
