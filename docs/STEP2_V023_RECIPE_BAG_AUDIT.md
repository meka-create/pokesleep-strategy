# STEP 2 v0.2.3 料理・食材バッグ計算改善（2026-10-16）

## 変更内容と目的
STEP 2の「計算できる料理が5品しかない」「初期食材を3種類しか登録できない」「食材バッグが無限容量になっている」というバイアスを改善した。ただし**週間エナジーの完全精度ゲートは未達**。

### 1. 料理マスター78品を搭載
- カレー／シチュー：25品、サラダ：26品、デザート・ドリンク：27品。
- 各料理に日本語名、料理カテゴリ、必要な食材名・必要個数、レベル0基礎エナジーを設定。
- 料理レベル70の倍率は `pokesleep-tool/src/util/PokemonStrength.ts` の `recipeLevelBonus[70] = 258` を使用。計算は `Math.round(baseStrength * 3.58)`。
- 旧5レシピのID `apple_curry` / `white_stew` / `apple_salad` / `bean_salad` / `apple_juice` は保持。以前の保存設定で同じレシピを選べる。
- データ出典： [ポケモンスリープ攻略・検証Wikiのレシピ一覧](https://wikiwiki.jp/poke_sleep/%E6%96%99%E7%90%86/%E3%83%AC%E3%82%B7%E3%83%94%E3%81%AE%E4%B8%80%E8%A6%A7)（2026年9月15日更新を参照）。差分は今後の自動更新STEP6へ。

### 2. 初期食材を19種類に拡張
- 手持ちの初期食材数を19種類すべて個別に入力できる。必要なものだけ入力し、未入力は0個とする。
- 編集欄は折りたたみ可能。試算設定は従来のローカル保存／JSONバックアップに含める。
- 旧バックアップの初期リンゴ・ミルク・マメミートなどの数値を維持し、足りないフィールドだけ0として扱う。

### 3. 食材バッグ容量の入力と上限処理
- バッグ容量を任意入力（`0`は未指定＝容量による制約計算をしない）。
- 初期食材数が入力した容量を超えている場合は計算を拒否。
- 回収時にバッグに入りきらない食材は、ゲーム内と完全一致するものではないが、期待値上「未回収のポケモン所持品」として残す。バッグ容量に関係なく全食材を得たと扱う過大計上を減らす。
- 食材が料理で消費された後の残り容量を次の回収処理に反映。
- バッグの空き容量判定は期待個数（小数あり）による近似。実際の端数・回収・ゲーム内UI操作に完全一致するものではない。

## 残る重要な制限・STEP2精度ゲート
1. **料理は手動で選択した1レシピを成立時のみ計上**。最もエナジーを稼ぐ料理の自動選択、余剰食材投入、代替レシピ、日曜日の大成功、料理補助スキルは未対応。
2. 食材バッグ容量はユーザーが入力する必要がある。未指定だと上限制約なし。所持品と食材バッグの実ゲーム確率状態は期待値近似。
3. メインスキルの多数は依然未対応。特に食材ゲット／鍋増加／てだすけ系の価値は計上されず、チーム順位付けのためには不足。
4. スキル発動順・げんき・所持上限と睡眠中の挙動、初期状態・週境界は定量ベンチマークが不足。実際の週間総エナジーを予測した数値とは扱わない。
5. upstreamの新規レシピや調整には自動追従していない（STEP6）。

**STEP2監査ゲート：継続／STEP3には進まない。**
