# W4 前半・独立安全監査（2026-10-27）

## v0.5.2追補：未保存編集の喪失と古い週間提案の見かけ上の有効性を修正

- ボックス検索など、データを変更しない画面再描画によって曜日別5匹の未保存編集が消える経路を確認。編集中の曜日・時間帯と保存済み計画／ボックスの同一性を保持する限りセレクト入力を維持する。CSV再取込・バックアップ復元などでボックス実体が変わった場合は古いIDの入力を引き継がず再描画する。
- 「日中21枠を一括設定」「手動睡眠7晩を一括設定」「前夜からコピー」が、現在の5匹の未保存編集を無確認で破棄できた。実行前に明示確認を追加し、拒否時は状態も未保存入力も不変更とする。既存の保存済み一括上書き確認は維持する。
- 日中編成・イベント・料理・計算条件の変更後も週間提案プレビューが表示され続けた。既存の適用時照合に加えて、条件変更イベントの段階で探索／旧提案を失効させる。CSV再取り込み・バックアップ復元・端末内全消去の保存成功時も失効させ、別のボックスや計画に旧候補が残らないようにする。
- 週間編集欄の未保存変更で、以前の通常7日間試算に古い計算条件の警告が付かない経路を修正。変更時に旧結果を「条件変更済み」と表示し、新試算は保存完了まで拒否する。
- ブラウザ仮想DOMの回帰に、検索再描画、拒否された一括設定／前夜コピー、保存失敗からの再試行、旧結果警告、条件変更・CSV再取り込み・復元・消去時の旧提案即時失効を追加。STEP2本体の数値式、週境界、CSV16列、JSON version:1、W2探索順位式には変更なし。

**ゲートの扱い:** 変更箇所の回帰、全テスト、ビルド、生成HTMLの完全一致、CI、Pagesを確認してからv0.5.2修正の完了可否を判定する。Android Chrome実機と実ゲーム順位はこの検証で代用せず、W4全体の正式承認を留保する。[Android Chrome実機チェック手順](W4_ANDROID_ACCEPTANCE_20261027.md)。

## W4で検出した修正対象
- **未保存の曜日別5匹編集**を抱えたまま7日間試算または週間自動探索を実行すると、UI上の選択変更が保存されていないため、画面とは異なる保存済みの編成で計算される危険がある。
- 条件が変わっても週間提案プレビューが残ると、以前の編成を新しいものと取り違える可能性がある。

## v0.5.1対処
1. 現在編集中の曜日・時間帯の5匹を記録し、保存前の変更がある場合は通常7日間試算と週間自動提案を拒否。対象の保存操作を案内する。
2. 曜日・時間帯・睡眠トグルを切り替える際、未保存の編集を破棄する前に確認する。拒否された場合は元の選択に戻す。
3. 週間提案後または探索中に編成セレクトを変更した時点で以前の提案を破棄し、現在の保存済み計画とは異なる結果を表示し続けない。
4. 以前の自動提案を適用する際にも未保存変更を拒否。
5. テストに、未保存変更による試算拒否・未保存の旧案適用拒否・保存後の試算再開・操作後の旧提案破棄を追加。
6. v0.5.1へ版上げし、index.htmlとdist/index.htmlを同じビルド成果に統一。
