# STEP 2 M3 — 複数個体の共有食材バッグにおける整数枠の競合（2026-10-23 / v0.2.70）

## 実際に再現した既存モデル内P1誤差

v0.2.69まで、`collect()` は5匹を固定順に処理し、先に処理した個体が回収した食材の**期待個数**を即座に共有食材バッグに加える。その期待値から算出した残り枠を、後の個体に対してあたかも確定した整数枠のように適用する。共有バッグの空きが1、先の個体Aと後の個体Bが各々独立に0個/1個を50%ずつ持つ人工例では、旧計算はA 0.5個＋B 0.5個＝1個を回収したと見積もる。しかし実際に1個以上持つ確率は `1-(1/2)^2=3/4` だから**期待回収は0.75個**であり、0.25個分の過大計上となる。5匹なら期待回収数は `1-(1/2)^5=0.96875`、旧期待値順次補充は1個。これは独立した有限列挙の人工例であり、実ゲームの観測精度ではない。

## 修正

- `collectSharedBagFoodQueues` を追加。最大5匹、各個体の `(所持数,食材数,満杯後のスキル抽選使用数)` 結合分布が既知で、初期の共有バッグの空きが整数のとき、空き0〜N個の確率を順番に更新する。Aが食材を取ったか否かを、平均に潰さずBの空き数に伝搬する。
- 個体ごとの回収済み食材期待値、回収後に残る食材とスキルキューの周辺確率、最終バッグ空き数の分布を算出。確率質量・整数の保存則を検証。
- 週次 `collect()` への適用は**全5匹**がこれまでの `queueFoodJoint` で追跡済み、共有バッグ初期空きが整数、回収途中に食材を挿入するメインスキルと追加おてつだい食材がないケース**だけ**に限定。これ以外は従来の期待値計算。空きが小数の期待値になった後などは後続時刻で多個体同時履歴を保持できない。
- 合計食材数・個別残存キューはこの操作内で分岐するが、**食材の種類と共有バッグ残量の全時系列の同時分布は未実装**。個体間の過去の相関を独立と仮定するので、これを週間最適編成の検証完了とみなさない。
- `exactSharedBagCollections` は新規の診断カウンター。既存のCSV16列、保存JSONの**入力スキーマ**、凍結M1、睡眠5匹固定、月曜04:00区切りには変更しない。
