# STEP 2 M3：整数食材1回抽選 → 最後の料理成立 → 週間げんき・きのみ分岐の限定接続

更新：2026-10-21 / v0.2.59

## 目的・対象

v0.2.58の独立1分週間時計算は人工条件CM04（初期りんご140・日曜夜のカレー1食欠損）と
CM05（初期りんご147・全21食成立）の**条件付き週間結果**を与える。
両方とも食材生産0%、メインスキル0%、固定睡眠5、日中固定5、初期げんき30、
睡眠スコア0、Lv50、食材バッグ500。CM05−CM04は料理+3,347、回復に伴うきのみ+420、
週間総計+3,767だった。

この数値は**ゲームの通常食材抽選に当てはめる確率ではない**。
本作業では人工抽選イベントを「日曜の最終料理の直前に、りんご7個または0個が
明示確率pと1−pで届く」と定義し、食材確率カーネルとCM04/CM05の独立7日時計算を
**研究用の限定接続**として結ぶ。

## 独立比較

- `PokeIngredientDistribution.certainIngredientBag({},7)` と
  `evaluateRecipeSequence` に、相互排他的な2分岐（7個/p、0個/1−p）を渡す。
  必須りんご7個のレシピが成功する確率pを、端数期待食材の代用なしに厳密計算する。
- そのpを**確定済み人工条件付き週結果**282,620と286,387へ適用する。
  別経路でベルヌーイ結果2通りを単純列挙して照合する。pは明示入力のみ、
  0, 0.01, 0.25, 0.5, 0.75, 1などで回帰する。
- p=0.25の試験値：成功期待食数20.25、料理期待値67,776.75、
  きのみ期待値215,785、**週間合計283,561.75**。
  「食事の直接エナジーだけの加算」は283,456.75であり、**きのみ効果105**を見落とす。
- 一般式（この人工条件に限定）：`E[weekly] = 282620 + p × 3767`。
  `E[cooking] = 66940 + p × 3347`、
  `E[berries] = 215680 + p × 420`。
  いずれもp自体をゲーム確率から推定していない。

## 非対応と完了ゲート

- **実ゲームで食材7個が1回のベルヌーイ抽選で届けられるという主張ではない。**
  現実のレベル/食材抽選・所持枠・バッグ・スキルによる食材到着時刻・種類・数量は共同分布がなく、
  M02/M03の21食目成立確率は引き続き未知。
- 料理が早い時間に不成立になればその後のおてつだい・発動スキルは違う。
  この研究では日曜夜の最後の1食だけに限定している。初期140対147という人工条件の
  げんき・スキル・所持数をゲーム一般へ外挿しない。
- 既存の `src/simulator.js`、生産モデル、料理算式、CSV/JSON、v0.2.30凍結M1と
  CM01〜CM03基準値は変更しない。**週間モデルの本番確率への自動接続は行っていない**。
- 元M01〜M04の完全週間4条件の独立外部照合0/4、代表R01〜R05ゲーム順位0/5、
  実ゲーム週観測0、M1主14条件の限定10/14は不変。
  **M1/M2/M3 PARTIAL、M4未着手、STEP2精度HOLD、STEP3未着手**。
