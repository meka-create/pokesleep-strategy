# STEP 2 M1 — 追加食材の不確実な料理エナジーと観測ゲート（v0.2.52 / 2026-10-20）

## 再現された問題

- `estimatedMeals` は必須レシピ食材が初期確定在庫から保証されない食数。
- `expectedSourceMeals` は**必須または追加食材**が不確実な生産期待値に依存する食数。
- よって `estimatedMeals = 0` かつ `expectedSourceMeals > 0` が成立する。v0.2.49〜v0.2.51の観測JSONは前者だけ保存していたため、必須食材が確定しているという理由で追加食材由来の料理エナジーを見逃す可能性があった。

## 限定修正

- 既存週間エンジンから出る `expectedSourceMeals` を記録時診断へ追加（既存3個＋追加1個）。新規記録は4カウンターすべて非負の安全整数とする。
- `expectedSourceMeals > estimatedMeals` では、差の食数が追加食材由来の不確実性を含むとして**比較保留**にする。差は真のエナジー誤差や料理成立確率の推定ではない。
- 旧3カウンターの観測JSONは読み取り可能なまま維持し、追加食材診断が保存されなかったことを理由にHOLDする。欠落・不正な値と、保存時から現在のカウンターの変化を区別する。
- 記録直後プレビュー・ブラウザー再比較・CLIの共通判定を維持し、人工モデル入力と週間シミュレーター入力の回帰テストを追加。

## 不変条件・証拠区分

- `src/simulator.js`、食材カーネル、旧M1凍結ファイル `docs/STEP2_M1_BASELINE_V0230_20261017.json`、週間計算エナジーの式、CSV16列・端末ローカル保存・睡眠固定と週境界の仕様は不変更。
- テストは**モデル内部の整合性を検査するC級証拠**であり、ゲーム内確率・週間獲得エナジー・R01〜R05の実際の順位を証明しない。
- M1/M2/M3 PARTIAL、M4 NOT_STARTED、ゲーム週観測0週、5組外部順位0/5、**STEP2精度HOLD／STEP3未着手**。
