# STEP 2 M1 — 週間実測JSONのサイト内読み戻し・最新版照合（2026-10-18）

## 目的と操作

v0.2.35では、ゲーム内週間まとめの数値と「試算に使った編成・個体・初期在庫」を一緒にJSON保存できるようになった。一方、保存後に比較し直す場合はNode CLI `npm run m1:observe -- ファイル.json` が必要だった。

v0.2.36では、**試算タブ内の「保存した週間観測JSONを読み込んで、最新版と比較する」**を開き、v0.2.35以降に作成した `pokesleep_weekly_observation_YYYY-MM-DD.json` を選択するだけで、以下をその場で確認できる。

- 実際に記録されたゲームの週間総エナジー・きのみ／直接エナジースキル・料理欄。
- 記録した試算時点の週間エナジーおよび現在の計算器で同じJSONの入力を再計算した週間エナジー。
- 実測−最新モデルの内訳別の差、**記録当時のモデルと今のモデルの差**。
- ゲームの二つの内訳の和が総エナジーと一致しない場合、未確認の条件、食材期待値に依存する料理計上の不確実性。
- **STEP2 HOLD／ゲーム精度・R01〜R05順位は未検証**という証拠境界。

## データの取り扱い

- 読み込んだJSONはブラウザー内だけで解析。外部アップロードしない。
- JSONの`input.box`、`input.teams`、`input.options`を一時的にシミュレーターへ渡すだけで、現在のボックス・睡眠用編成・端末内保存データへは一切書き込まない。
- 拡張子JSONのファイルを選び、サイズ8MB以下だけを受け付ける。スキーマ`step2-m1-weekly-observation-v1`、本物の月曜日、フィールド一致、正の値または0の安全整数、出典文字列、真偽値形式の確認項目、試算時点の内訳などの最低条件を検証する。
- すべての値はHTMLとして挿入せず**`textContent`**として画面に表示する。入力JSONに含まれる個体名・文字列を実行コードとみなさない。
- `screenshotReviewed` は**常にfalse**。チェックボックスがすべてONでも、週の生データ1点は`UNCALIBRATED_OBSERVATION`以上に昇格しない。記録の出典や画像自体をプログラムが独立確認したと主張しない。

## 回帰と比較規約

- ブラウザー用`PokeObservation.reviewImportedReport`は、受け取ったJSONの予測値を信用せず、**JSONに記録されている入力で現在の`PokeSimulator.simulate`を再実行**。記録当時の予測値との差があれば「要確認」を表示する。
- 既存CLI `compareSingleWeek` と同じ**実測きのみ欄＝モデルきのみ＋直接エナジースキル**で照合し、総差と内訳をNodeテストで比較する。
- `estimatedMeals` に含まれる料理成立を保証しないこともCLIと同様に留保する。
- `tests/step2-m1-observation-import-replay.test.cjs`は正規JSON、モデルドリフト、日付・フィールド違い・不正整数・出典詐称・確認フラグ型、ゲーム週まとめ矛盾などを検証。
- `tests/app_boot.test.cjs`のブラウザー操作テストで、v0.2.35の保存操作で得たJSONを再度読み込み、再計算結果を表示できること、端末保存データが変わらないこと、異常ファイルで前回の結果を消してエラーを表示することを確認。
- `index.html` と `dist/index.html` の完全一致を既存CIで維持。

## 検証区分

この機能は既存M1の**実測入手〜照合の操作を簡素化しただけ**であり、実ゲームの記録0件という状況を変えるものではない。実ゲームの抽選確率、スキル発動の時刻・料理成立率・編成順位を新たに証明していない。

M1は14件中10件限定B照合、混成M01〜M04未検証、R01〜R05の実ゲーム順位は5組とも未検証。**M1 PARTIAL、M2 PARTIAL、STEP2 HOLD、STEP3未着手**を維持する。
