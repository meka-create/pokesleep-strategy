# STEP 2 M1 — 実ゲーム週間まとめの記録を試算画面へ接続（2026-10-18）

## 背景

既存の `scripts/step2-m1-observation-compare.cjs` は、週まとめの実測と週間シミュレーターを比較するが、`docs/STEP2_M1_WEEKLY_OBSERVATION_TEMPLATE.json` を手作業で埋める必要があった。試算のフィールド・朝昼夜5匹・睡眠5匹・初期食材19種・料理条件・ボックス個体を再転記すると、実測の誤差と**入力の取り違え**を区別しにくい。

v0.2.35では、試算結果内の折りたたみ「実ゲームの週まとめを記録して、試算と比較する」からユーザーの実際の週まとめ数値を入力し、**成功した試算そのものの設定・元の予測値**とともにJSONを保存できる。外部への自動送信や観測データの恒久保存はしない。

## 操作

1. 「イベント」で**実測週のフィールド・料理カテゴリ・キャンプチケット等**を設定し、必要な手持ちと日中・睡眠5匹を設定する。7日間の試算を実行する。
2. 試算結果の一番下で「実ゲームの週まとめを記録」を開き、対象週の**月曜日の日付**、ゲーム内週間まとめの **総エナジー**、**「きのみでのエナジー」欄**、**「料理でのエナジー」欄**を整数で入力する。ゲームの「きのみ」欄にはエナジーチャージ等の直接エナジースキルの寄与が含まれるため、別途スキルエナジーを足さない。
3. イベント、回収時刻、アイテム、開始値、月曜4:00〜7:30の境界について、**本当に確認した条件だけ**チェックする。5つとも初期OFF。画面に実数値があることを確認して最後のチェックを入れる。スクリーンショットのファイル名は任意。
4. 「週間実測と試算条件をJSONで保存」を押す。入力の矛盾と未確認条件数が表示され、`pokesleep_weekly_observation_YYYY-MM-DD.json` をローカルに保存する。
5. JSONは既存のCLI `npm run m1:observe -- path/to/file.json` で照合できる。ChatGPTに共有する場合は**ポケモン個体情報やニックネームを含む**ことを理解してから添付する。

## プログラム上の安全策

- `src/observation.js` はブラウザー／Node共通の生成・検証モジュール。日付は厳密な**実在する月曜日**のみ。実測値は0以上の安全整数・空欄拒否、確認済みの週まとめチェックが必須。確認事項5項目はbooleanで保存し、文字列 `"false"` は拒否する。
- `captureSimulation(input,predicted,...)` が**成功した試算で使った入力・結果を深くコピー**する。後でイベントやボックス・料理・編成を編集しても、観測JSONでは試算値と入力を同じ実行に結び付ける。次の試算時に観測フォームの入力値・チェック状態を初期化する。CSV/バックアップの復元・全消去時は旧試算結果も隠す。
- 保存ファイルの `schema` は既存の `step2-m1-weekly-observation-v1` を維持する。`input`、`week`、`observed`、`provenance` に加えて、`capture.appVersion`、`capture.capturedAt`、`capture.modelAtCapture` を付ける。余分なフィールドは既存の読み取りと互換。
- CLIは `capture.modelAtCapture` と**現在のコードで再実行した予測値**を照合する。差があれば `captureComparison.matchesCurrentModel=false` として交絡要因へ追加し、精度を検証できる観測と誤認しない。スクリーンショットについては、JSONの識別子を受け取っても `screenshotReviewed=false` のまま。
- ゲーム側の週まとめ「きのみ」には直接エナジースキルを含み得るため、比較は `モデルのberries+skills` と実測の「きのみ」欄で行う（既存CLIと同じ暫定対応）。実測総エナジーと二つの欄が不一致なら**矛盾を隠さず警告**する。
- 観測値と試算値の差分表示は**未校正の単週値の差**。ランダム抽選によるブレや未対応イベントを含み、編成の優劣やモデル精度は判定しない。フラグ5つをすべて確認しても `UNCALIBRATED_OBSERVATION` のままで `accuracyGate=HOLD`。

## 回帰の対象

`tests/step2-m1-observation-capture.test.cjs` で、週の月曜日判定・整数ゼロ/負数/空欄・確認フラグ・撮影ファイル名・スナップショット固定・差分・週まとめ矛盾・旧CLIへのエンドツーエンド受け渡し・キャプチャと現在のモデル値不一致の保留を検証。HTML生成は `build.mjs` を通して `index.html` と `dist/index.html` の両方をCIで厳密一致させる。

## 判定境界

この変更は**実測を収集できる導線を作った**ものであって、現時点でゲーム実測が集まったという成果ではない。M1は14条件中10件限定B照合・混成M01〜M04の4件未検証、元のR01〜R05ゲーム順位は5件とも未検証。**M1 PARTIAL・M2 PARTIAL・STEP2 HOLD・STEP3未着手**を維持する。

次はこの記録から実ゲームの同条件週間データが取得できた範囲でのみ、誤差の原因・発動タイミング・料理成立と比較順位を確認する。ゲーム実測を作り出して結果を良く見せることはしない。
