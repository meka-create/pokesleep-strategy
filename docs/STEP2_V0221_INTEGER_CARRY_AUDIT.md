# STEP 2 v0.2.21 — 整数所持数確率分布と満杯境界の監査

日付：2026-10-17（JST）。**STEP2精度ゲート：HOLD、STEP3未着手**。

## 背景

従来は「おてつだい平均獲得個数 × 回数」と「残り枠÷平均獲得個数」を使ってポケモン自身の所持枠の上限を判定していた。そのため例えば**空き1枠にきのみ2個**という1回のおてつだいを「0.5回だけ実行」として処理しており、おてつだい抽選・満杯・いつのまに育成の確率が不整合だった。

根拠：
- [ポケモンスリープ攻略・検証Wiki「最大所持数」](https://wikiwiki.jp/poke_sleep/最大所持数) — きのみ・食材の整数共有所持枠、超過する食材の切り捨て、きのみエナジー移行、追加おてつだい999枠
- [ポケモンスリープ攻略・検証Wiki「おてつだい」](https://wikiwiki.jp/poke_sleep/おてつだい) — 満杯後のいつのまに育成では食材・スキル抽選停止
- [ポケスリ攻略・検証「きのみの数S」](https://wikiwiki.jp/poke_sleep/サブスキル/きのみの数S) — 1おてつだいのきのみ個数と満杯への移行

## 実装

- `integerPocketTransitions`：0〜所持上限までの**整数所持数→確率**の疎なMap分布を保持し、通常のおてつだい完了ごとに次の分布へ遷移。
- 分岐ごとにきのみ `berryPerHelp` 個を `1-ingRate` 確率で取得、または解放済み食材枠のうち1種類を `ingRate / unlockedSlotCount` 確率で取得。小数の「半回おてつだい」は行わない。
- 所持枠が空いている場合、その1回はスキル抽選資格あり。きのみ・食材の整数取得を所持枠上限で制限し、超過きのみはいつのまに育成に回し、超過食材は破棄。
- **すでに満杯の分岐**はスキル抽選と食材を停止してきのみだけを自動生産。未回収エナジーは週末月曜04:00時点で旧週へ加算しない従来仕様を保持。
- 確率分布の平均占有数を `bag.used` とし、きのみ・食材・スキル資格・いつのまに育成の期待値は分岐ごとに集計。追加おてつだい専用999上限は引き続き別の期待値処理。
- **共有食材バッグが満杯で回収できない**食材の残り個数は、整数2点分布 `expectedPocketOccupation` で平均を保存しながら再構成する近似であり、厳密な食材組み合わせの同時確率は未対応。複数のポケモンでのスキル抽選と占有の相関も未モデル化。

## 新規9件の回帰

1. 空き1枠で2個きのみを獲得：1個保持、1個いつのまに育成、スキル資格は1回
2. 次のおてつだい：所持満杯につききのみ2個をいつのまに育成、スキル資格0回
3. きのみ50%／食材3個50%、容量3の確率分岐と次のおてつだいの期待値
4. 食材4個を引いて空き1枠しかない場合1個だけ保持
5. 解放済み2食材枠の等確率配分と整数所持数
6. 回収後の端数平均占有数を整数2点分布に再構築
7. 負数・不正な確率・最大所持数不整合の入力防御
8. 20回のおてつだい後の確率質量保存と平均占有数＝平均きのみ＋食材
9. 実際の7日間計算で完了おてつだいとスキル資格の大小関係が破綻しないこと

上記の単純分岐値は手計算で独立に検算。CIのNode.js22実行と生成HTML一致が確認できた場合のみ回帰PASSを記録する。
