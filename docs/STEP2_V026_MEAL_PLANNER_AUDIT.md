# STEP 2 v0.2.6 — 料理の選択・食材消費・料理後げんき回復

更新：2026-10-16。**STEP 2精度ゲートは引き続き保留。**

## 今回の実装
- 78レシピから、毎食時点の**料理カテゴリ・食材在庫・その食事の鍋容量**で成立するものを評価。
- 料理モード：
  - `fixed`（旧データの既定）：指定レシピが成立する場合だけ作る。
  - `fallback`：指定レシピを優先し、作れないときはその時点で作れる最も高エナジーのレシピへ代替。
  - `best`：カテゴリが確定している場合、毎食の成立候補から**Lv70レシピエナジー最大**を選ぶ。
- 強さ同点のレシピは必要食材数が少ない方、その次はレシピIDの昇順で決定（再現可能な結果）。
- 食事が成立すると必要食材を在庫から差し引き、料理の記録（曜日番号・朝昼夜・料理名・必要食材総数・鍋容量・獲得エナジー）を残す。週内の食材消費も集計。朝・昼・夜の最大21食の記録をUIに表示。
- 調理後、その時点でフィールドにいるポケモン5匹にげんき回復：80%以上+1、60〜79%+2、40〜59%+3、20〜39%+4、20%未満+5。**料理が成立した場合のみ**。性格などの回復への個別補正や調理中の細かな操作は現状簡易モデル。
- レシピ選択と既存の鍋拡張スキル、日曜の容量2倍、いいキャンプチケット、食材バッグ容量を連動。
- 保存形式v1に`simulation.recipeMode`を追加。過去のバックアップや保存済みデータでこのキーがない場合は`fixed`として扱い、既存の指定レシピの扱いを維持。

## 計算上の制約
1. **「best」は毎食の局所的な最大化（貪欲法）**であり、先の食事や翌日・翌週を見越した料理・在庫の連鎖最適化ではない。ゲーム内のランダムな「おまかせ料理」とも異なる。
2. 料理カテゴリが`random`なら、選択された料理のカテゴリが確定できないため**料理エナジーは未計上**（3カテゴリを勝手に平均したり、確定したりしない）。
3. レシピはすべてLv70を仮定。未習得レシピと実際に選択可能なレシピの区別はまだない。
4. **追加食材、余剰鍋容量を満たす食材の投入、ごちゃまぜ料理、大成功／料理チャンス／イベント料理倍率**は未計上。食材所持数は期待値で端数を含む近似のため、実際にレシピが成立する確率とは異なる。
5. 料理で回復するげんきの変化によるおてつだい数の修正は15分刻み近似。開始時の個体ごとのげんき・週跨ぎの所持品は未対応。
