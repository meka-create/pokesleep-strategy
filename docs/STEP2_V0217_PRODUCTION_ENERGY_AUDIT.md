# STEP 2 v0.2.17 — おてつだい生産とげんき速度帯の監査

日時：2026-10-17 JST。**STEP 2計算精度ゲート：HOLD**。

## 背景と一次資料

ポケモンスリープでは、おてつだいが完了するときのみきのみ・食材が生成され、スキル抽選も発生する。最大所持数超過分はいつのまに育成となり、スキル抽選しない。出典：[ポケスリ総合資料サイト・用語](https://wiki.pokesleep.com/ja/glossary)、[ゲームエイト「いつのまに育成」](https://game8.jp/pokemonsleep/584756)、[攻略・検証Wiki「おてつだい」](https://wikiwiki.jp/poke_sleep/おてつだい)。

v0.2.16までスキル抽選は完了整数ヘルプを採用していた一方、通常生産は15分の期待おてつだい 0.2～0.8 回を毎回加算していた。日/週境界や短時間で**未完了のおてつだいを先取りしてしまう不整合**があった。

## 改修

- `completeHelpProgress` をスキル抽選だけでなく、通常生産（きのみ、食材、いつのまに育成）へも共通適用。未完了周期は15分・回収境界をまたいで引き継ぐ。
- 編成から外れた個体の未完了進捗は破棄し、残留個体の進捗は維持。追加おてつだいによる付与分は通常周期を進めず、従来どおり期待値で別枠999上限。
- `weightedHelpMinutes` を追加。15分間のげんき変化を線形（-1/10分）とする現在のモデル内で、80/60/40/1の速度境界に区切って `∫dt / energySpeed(energy(t))` を解析的に積分。中間値一点で15分を代表させる誤差を解消。
- `queueSneakyEnergy` / `releaseSneakyEnergy` により、いつのまに育成エナジーを**次の実際の回収操作まで保留**。日曜深夜00:00～月曜04:00の未回収分は旧週のエナジーに加算せず `pendingSneaky` に診断値として残す。食材バッグとポケモンの自身の所持枠は別であり、食材バッグが満杯だからという理由で通常スキル抽選は停止しない。
- `skillHelpCompletions` は全個体の通常完了ヘルプ（整数）となり、`skillEligibleHelps` は所持枠内で抽選資格のあるヘルプ期待値（端数可）として公開。既存のCSV16列／ユーザー保存JSONのキー・仕様に変更なし。結果内の診断用キーのみ追加。

## 境界の数値検算

**境界例**：げんき80.5から15分で79.0へ連続減少する15分間。
- 最初5分は速度係数0.45、後半10分は0.52。
- 厳密な帯域別仕事量（従来の線形げんき減少モデル内）：`5/.45 + 10/.52 ≈ 30.34188034` 等価分。
- 中間7.5分のげんき79.75を使う旧式：`15/.52 ≈ 28.84615385` 等価分。
- この差は**モデル内の演算差**であって実機計測の精度改善率ではない。

**完了前架空生産**：極端に遅い基礎時間を一時的にテストマスターへ設定し、7日間におてつだい完了が1回もないケースで `berries=0`, `sneaky=0`, `skillTriggers=0` を検証。

## 追加回帰検証

計11テスト追加：速度帯内定常、80境界、1境界、分割積分の加法性、不正値防御、未完了生産禁止、完成ヘルプ/資格ヘルプの整合、食材バッグ満杯でもポケモン所持枠があればスキル抽選すること、いつのまに育成の回収保留・二重計上防止・負値拒否、月曜04:00の未受領残高。

## 未達成事項

- 生産物がきのみか食材かの**各回抽選**、1回の生産個数・最大所持数の境界、食材バッグの整数容量は依然**期待値**。満杯の際の資格割合 `fits` が端数になり、スキル抽選側で1回ベルヌーイ近似を継続。
- げんきの実ゲーム内部は10分ごとのエネルギー減少イベントやメインスキル回復イベントを伴い、今回の線形帯域積分は**15分刻み線形げんき減少近似に対してのみ**厳密。ゲーム実時刻を忠実に再現するものではない。
- 編成変更時の内部予約キュー、通常ヘルプ周期の確率性、スキル発動秒と回復による速度変化、週間食材・料理の連鎖最適化は未完成。
- 主要ポケモンによる実測週間エナジーとの差分・Android Chrome実機確認は未実施。前週所持品の初期状態も未対応。

**独立の数値ベンチマークとAndroid実機検証、ユーザー承認なしでSTEP 3へ移行しない。**
