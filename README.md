## v0.2.17 生産時刻の整合・げんき速度帯の精密化
従来は15分単位の小数のおてつだい（例：0.25回）でも**きのみ・食材・いつのまに育成**を直ちに計上していました。v0.2.16で改善済みのスキル抽選だけでなく、通常生産も「完了した整数回のおてつだい」にそろえ、未完成の周期は次の時間帯へ繰り越します。パーティ離脱時のみ周期を破棄し、終了した週の未回収品は従来どおり加算しません。

**いつのまに育成を回収操作まで保留**し、日曜深夜00:00～翌月曜04:00の未受領エナジーを旧週へ架空計上しないように修正しました。診断値 `pendingSneaky` に週末未回収量を保持します。食材バッグとポケモン自身の所持枠は別で、食材バッグが満杯でもポケモンの所持枠に空きがあればスキル抽選を行います。

15分中にげんきが80・60・40・1の速度境界を横切る場合は、中心時点の速度で15分全部を計算する代わりに、**各げんき速度帯の滞在時間を積分して生産進捗を計算**します。げんきは従来の1/10分の連続的減少近似を使い、実ゲームの10分単位の内部時刻まで完全再現するものではありません。バッグ満杯の瞬間・1回ごとの食材/きのみの抽選・個々のスキル発動秒は未再現です。[監査](docs/STEP2_V0217_PRODUCTION_ENERGY_AUDIT.md)。STEP 2全体の精度ゲートはHOLD。

## v0.2.16 完了したおてつだい回数によるスキル抽選
15分ごとの期待おてつだい数（0.3回など）を毎回独立にスキル抽選へ使う方式を廃止し、**個体ごとの未完了おてつだい進捗を持ち越し、累積1.0回に到達して初めて抽選**する方式へ改善しました。交代で外れた個体の途中進捗は消去し、残留した個体の進捗と不発天井履歴は維持。週末・睡眠時間帯も従来の回収制約を保持します。食材やきのみの生成個数は引き続き期待値近似です。

## v0.2.15 連続不発天井とスキルストックの同時確率計算
従来の「ピティ込み長期平均発動率」を各おてつだいに適用する方式を撤廃し、**連続不発回数と待機スキル0・1・2回の同時確率分布**で抽選・保管・回収を計算します。天井到達時は確定発動、満杯時は以降の抽選停止、回収時は待機スキルだけ0に戻し不発履歴は保持。同じ5匹内の位置変更ではストックは変化せず、1匹でも交代すれば関係するメンバーの待機スキルを消去します。天井78回／スキルとくい種族別基準時間換算はpokesleep-toolを一次実装参照し、旧来の平均率より有限7日間の状態遷移を優先します。

## Android Chromeで試す
`index.html`（または `dist/index.html`）はCSSとJSをすべて内蔵した **単独HTMLファイル** です。ZIPを展開して `index.html` をChromeで開きます。ファイルを開く方法によってはAndroidのファイルマネージャーがプレビューを表示することがあります。その場合は「Chromeで開く」を選択してください。ファイルURL上のlocalStorageは端末や起動方法により動作が異なるため、**JSONバックアップを保存**してください。

PCの場合は `index.html` を直接開けます。開発時は `python3 -m http.server 8765 --bind 127.0.0.1` 等でローカル配信できます（LANには公開しません）。
