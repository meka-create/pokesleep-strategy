# U3-A 再設計：ユーザーが迷わない三段階導線（2026-11-04）
**ステータス：設計差し戻し。v29は承認済み完成版ではない。コード変更前の再実装計画。**

## 1. 受入フィードバックと原因
2026-11-04 U3-D配布ZIPを確認したユーザーから「準備週、イベントはじめ、イベント中でページ表示や入力のしやすさに導線があるのか分からない」と指摘された。**NGとして正式記録**。未確認を合格にしない。

ソースを確認するとv27以来のU3-Aは `arrangePhaseLayout()` で **U3内部の5カード（準備案内・イベント条件・睡眠設定・提案ボタン・週間編成）をDOM順に並べ替えるだけ**。準備案内にU2リンクを置いた一方、U2はU3へのリンクしか変更されておらず、初期操作からイベント開始まで「何をいつ入力し、どのボタンで次へ進むか」は設計されていない。イベント中に週間編成が先頭に来るのも採用作戦があるときだけ。v28の当日曜日・v29の安全ゲートは重要だが、**全体のUX導線完成の証拠ではない**。

## 2. 絶対に維持する決定
- 準備週 → イベント開始 → イベント中 の明快な操作導線。イベント中は当日の週間編成を一番よく見る画面に。
- 日中21枠＋21食は自動提案・閲覧のみ。**個別手動編集は廃案、復活禁止**。睡眠7晩の手動設定・自動OFF初期・ON自動提案は維持。
- U2は準備目標／食材在庫。イベント条件はU3の一か所に集約。**二重入力を作らない**。
- 備蓄計画は料理数最大化でなくイベント週エナジーを重視、カテゴリ未確定なら3カテゴリを均衡。実計算の完成は後工程。
- 04:00 JSTのゲーム曜日で火曜→火曜、水曜→水曜。再読込で今日を選び直すが、閲覧中の手動曜日選択は保持。
- 週別在庫/採用作戦、提案→レビュー→明示採用、過去・現在時間帯の保護、保存済み0個と未保存の区別、必須条件インターロック。
- 1週間イベントのみ。v29の原本（U3 blob `6f258db5f053641ab0b31b37addcce80e8cfd31a`、U2 blob `9857040cc46cd0269b8261e779c3b2da24d897d9`）を凍結。v16/v24起点の作り直しを禁止。

## 3. 新しい導線仕様（入力を増やさない）

| 場面 | 最初に見る画面・情報 | 主操作（原則1つ） | 次に自然につながる動作 |
|---|---|---|---|
| 準備週 | **U2：備蓄目標**（どの食材を何個） | 食材在庫へ／保存 | 在庫を保存したら「イベント条件を確認」からU3へ。**未確定カテゴリでも備蓄目標は見られる** |
| イベント開始、条件不足 | **U3：未確定のイベント条件**（不足項目を短く特定） | 条件を設定・保存 | 入力完了と未完了を一目で区別し、次の「作戦を提案」が有効化 |
| 開始後、条件充足・未採用 | **U3：作戦を提案**が主役 | 7日間の作戦を提案→確認→採用 | 採用後は設定フォームを閉じて「今日の週間編成」へ移る |
| イベント期間中、採用済み | **U3：今日のパーティ3枠＋料理3食＋睡眠編成**が即座に見える | 通常は閲覧だけ。必要な場合だけ「食材在庫を更新」 | U2の食材在庫を保存後、U3へ戻って**残り期間を再提案**。確認・採用するまで旧作戦は保持 |
| イベント終了 | U3：保存済み作戦の閲覧 | なし（必要なら履歴確認） | 新規提案不可 |

- ユーザーに「準備／開始／期間中」を選ばせる新しい手動切替UIは不要。**イベント開始日と採用状況・保存済み条件**から、必要な操作を自動で提示する。
- UIは**現在必要な1アクションを強調**し、他の設定は小さな折りたたみや副次的導線で扱う。「手順説明の長いカード」「重複ナビ」「新しい大量の入力フォーム」は作らない。
- 別ページのままのU2/U3間でも**状態・イベント週・戻り先**が自然につながる設計にする。U2の保存完了直後に次の行動が分かる。リンクがあるだけではPASSとしない。
- イベント期間中に開いたU3で**今日の編成が採用済みなら無条件に最上位**。条件未確定/未採用なら、その状態を隠してダミー編成を表示せず、必要な操作へ誘導する。
- 実装対象はUIモック。イベントオンライン自動取得/料理最適化の動作を実装済みと見せない。

## 4. 実装工程と検証ゲート

**U3-A2-1：ユーザー導線を一画面遷移単位で設計**
- 入口の主役(U2目標/U3条件/U3当日)・必要な操作・保存後の戻り先を具体的に固定。
- UIデザインは現行v29のコンパクトさを維持し、操作が実際につながるようにする。まずv29を基に別版へ改修。

**U3-A2-2：U2/U3の双方に実導線を実装**
- U2の在庫保存後に自然な次操作（イベント条件確認／作戦画面へ戻る）を表示。
- U3の未確定条件→確定後提案→採用→当日編成と、イベント中の在庫更新→再提案を**画面間で往復操作可能**にする。
- 余計な新たなタブ・入力項目・昼間21枠の個別編集を作らない。

**U3-A2-3：実操作シナリオの回帰**
- **PREP→START→ACTIVE**：U2目標閲覧→U2在庫保存→U3必須条件→提案→レビュー→採用→当日編成。
- **ACTIVE→U2→ACTIVE**：水曜日にU3を閲覧→U2在庫変更/保存→U3に戻る→更新の検出→再提案→過去・現在の編成/料理を固定→採用。
- **04:00前後／週切替／未保存0個／NG条件／睡眠7晩／廃案UI不在**をv29のゴールデン差分監査とChromium E2Eで検証。
- 単に `main` のDOM順が変わっただけで成功と判定しない。**タップ操作で段階を進めること**をテストする。

**U3-B/C回帰→U3-D実機再受入**
- 当日曜日04:00、7晩、条件ロック、保存・採用を再検証。
- v29以前の原本を保護。**ユーザーの実機で「導線が分かる」「当日の編成が見やすい」両方を確認して初めてU3-D承認候補**。
- 現在のU3-D実機結果は**NG。差し戻し。U4へ進まない**。
