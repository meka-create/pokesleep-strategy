## 段階別に変えた順番と理由

| 状況（JSTのイベント日時と採用状態） | 画面の先頭と優先順位 | イベント条件 |
|---|---|---|
| **準備週（イベント前）** | 「準備週」1行のコンパクト案内 → U2準備目標/在庫へ → イベント条件 → 睡眠編成 → 提案 | 原則折りたたみ。必要な時だけユーザーが開く |
| **イベント開始〜採用前（開始日04:00以降）** | イベント条件 → 「7日間の作戦を提案」→ 睡眠設定 | 必須のイベント条件が未確定なら初回表示で展開。ユーザーが閉じた後は勝手に再展開しない |
| **イベント中・採用済み作戦あり** | **週間編成（最上位）** → 睡眠編成 → 再提案／在庫導線 → イベント条件（下段） | 原則折りたたみ。変更が必要ならいつでも開ける |
| **イベント終了・採用済み作戦あり** | **保存された週間編成（最上位）** → 睡眠設定 → 操作（再提案禁止）→ 条件 | 保存済み作戦の閲覧は可能 |
| **イベント終了・作戦なし** | 「イベント終了」案内 → 条件 → 操作（提案禁止） | 無理に見本の編成を実績として表示しない |

- フェーズ判定はv26の `eventPhase()` と `hasApplied`／`appliedEventStart` を再利用。実ゲーム日付判定の変更は行わない。
- キーボード・読み上げ順が見た目とずれないよう、**CSSのorderでなくDOM要素の並び順を段階切替時だけ変更**。フォーム入力中の繰り返し移動でフォーカスを奪わない。
- 新しい「運用中/提案」切替タブやイベント重複設定は追加しない。U2の準備入力はU2だけ。
- 説明は必要最低限、通常運用時は新しい準備案内カードを非表示とする。
