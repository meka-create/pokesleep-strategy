# M4 v133：3カテゴリ備蓄とイベント週料理確定の不一致修正（2026-11-27）

## 実機報告と根本原因
Pixel 7aのM4一括受入で、**「集めておく食材」3カテゴリを保存し、在庫を保存後、イベント週の料理を1カテゴリに確定して「作戦を提案」すると「備蓄レシピまたは食数が現在の条件と一致しません」と表示される**不具合を確認。

v132の `e7-f4c-integrated-v112.js` の `prepPreference` が、`p.categories.some(cat=>c.fields.food!=='all'&&c.fields.food!==cat)` を不正扱いしていた。同じ制限が `e7-f3-prep-goals-v88.js` にあり、料理確定後の準備目標表示も不適切に停止していた。F3の3カテゴリは料理が未確定な時の備蓄候補であり、イベント週の1カテゴリ確定と矛盾しない。

## 修正
1. F3の備蓄目標と保存レコードは**3カテゴリのまま**保持。料理確定によるF3表示停止を解除。
2. F4/F5は共通の読み取り専用 `f3/f3-m4-food-preference-v133.js` で、**今週作れる料理カテゴリとの共通部分だけ**を優先条件として評価。イベント料理`all`なら全カテゴリ、1カテゴリならその1カテゴリ、備蓄に該当カテゴリがなくても備蓄設定を消さずに通常の料理探索を実行。F4/F5の料理種別検証は一切緩めない。
3. 食材バッグの保存条件検証は**元の全3カテゴリ**に対して引き続き行い、単に1カテゴリを切り出して見かけ上のバッグ容量を増やさない。M3整合表示は今週対象のカテゴリだけと比較し、除外された準備カテゴリとその保持を明示。
4. F5残期間にも同じ投影を使用し、過去予測・現在の食事・匿名ID・イベント所有者・保存revisionを不変に保持。既存のF4/F5 M1計算式・手動7晩テンプレート・元69個体CSV・正式rootを変更しない。
5. `tests/f4-m4-v133-prep-food.test.cjs` と `tests/f5-midweek-v119.test.cjs` で料理タイプ3通り／`all`／対象外／不正データ、実際のF5残期間の探索を回帰。Chromium実機相当 `tests/preview_browser_f3_prep.py` で**3カテゴリ→料理カレー確定→3カテゴリ備蓄目標維持→元条件復元**を確認。PWAオフラインキャッシュを更新。

## 検証と受入ゲート
- PR最終HEADで2系統CI、main統合後はValidate STEP 2 / Validate PokeSleep Strategy / Verify E7 preview publication inputs / Pagesの同一SHA SUCCESSを必須とする。
- **自動CIの成功はPixel 7a実機での再受入PASSではない**。Issue #228 M4-05/M4-06の今回の操作を同じ保存済み3カテゴリで再実施し、「作戦を提案」が次の正常操作へ進むこと、備蓄3カテゴリが消えないことを確認する。
- 不具合が解消してもM4一括受入全体をPASSとは判定しない。M4の残項目が確認されて初めてM5へ。
