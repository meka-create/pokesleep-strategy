# F4-C v104：実個体の安定IDとローカル参照作戦保存（2026-11-14）

## 実装意図
- v103-A main `979f79658f0269552f7e580ca4119185498c497e`から継続。11/16追加の20食材・81料理の公開までは、独立して完成できる**実個体ID再照合／参照用週間作戦の保存・復元基盤**を先行開発。
- v99の `f4/f4-c-stable-box-ids-v1.js` の純粋台帳を利用し、v104新規 `f4/f4-c-local-draft-v104.js` がWeb Crypto SHA-256と暗号学的乱数UUIDによるローカルだけの匿名識別を提供。
- データ本体に個体のニックネーム・種族・性格・個体設定の生値は保存せず、端末側で個体CSV 18列から正規化した行に塩付きダイジェストを割り当てる。ソルトとダイジェスト自体も**公開・送信禁止、端末専用**。同一構成の個体の並べ替えは識別不能なため、参照された個体に完全一致重複がある場合は、たとえ行番号が変わらなくても保存を拒否する。個体レベル等の変更も自動で別個体へ付け替えず再確認を要求。
- `saveLocalReference()`：**明示同意** `SAVE_PROVISIONAL_LOCAL_DRAFT` がある場合のみ、既存のF4-C v101/v102で生成した29窓の暫定結果を現在の実ボックス・F1対応個体・料理ID・7晩睡眠固定・前週日曜の睡眠持越し・朝主副/昼夜主ヒーラーと照合し、不透明IDに変換して**独立した端末ローカルキー**へ参考下書きを保存する。
- 保存キーは `pokesleep-strategy-f4c-v104:local-reference-only`。既存E7の `plan`、`box`、`inventory`、`conditions`、`player`、`selected` を書き換えない。保存は1 JSONレコードで台帳と最大16イベントの下書きを一体更新し、更新直前の内容・revisionを確認するベストエフォートの楽観的競合検出。複数タブに対する真のトランザクション隔離を保証するものではない。
- `restoreLocalReference()`：現在のE7イベントID・週・条件改訂・在庫改訂・F1ソースコミットと端末内ボックス再照合により、CSVの**一意な行並べ替え・一意な追加**なら正しい現在行インデックスに戻す。対象個体削除、設定変更、同一構成重複、イベント/在庫条件差分、料理ID消失、ヒーラー資格変更、29窓の不一致ではBLOCKED。端末への書込みゼロ。
- データ契約は `REFERENCE_DRAFT_SAVED/RESTORED`、`officialPlanAdopted:false`、`weeklyEnergyCertified:false`、`writesExistingE7Data:false`。**参照作戦は正式採用されない**。開発プレビューでは依存スクリプトを読込可能にしたが、本番E7のUI／保存構造／自動採用機能は未変更。

## 保護・制限
- 実機端末のブラウザ `crypto.subtle` と `crypto.randomUUID` が必須。疑似乱数、インデックス由来ID、暗号化できない環境ではBLOCKED。塩付きSHA-256は同一個体の保持と改ざん検知のためであり、端末外への完全匿名性を保証するものではない。
- v99の台帳仕様は、同一構成重複が行数/並び替えで曖昧な場合に中止する。将来必要ならユーザーによる個体単位の識別承認を別途設計する。
- 故障中の `localStorage`、別タブの同時更新・破損JSON・不正な入力・想定外の保存内容を補完せず中止する。成功レスポンスは実際の保存値の読戻し一致後のみ。正式採用にはF4-C全補正と確定出典、E7の書込スキーマと独立監査が必要。
- 69個体CSV・ニックネーム・個体構成・実在庫・識別ハッシュはいかなるpublic GitHubテストデータやログにも含まない。合成データで回帰。
