## 2. アプリのフェーズは自動判定、画面を強制切替しない
ユーザーに「準備週／イベント開始／イベント中」手動選択トグルを追加しない。ゲーム日付JST04:00と、条件の確定・食材在庫の保存・作戦の採用状態で**今必要な操作を決める**。ユーザーが別タブ・別曜日を閲覧中なら勝手に戻さない。

| 状況 | 初めて開いたときの主役 | 唯一の主操作・省略条件 |
|---|---|---|
| イベント開始前 | **準備**の目標タブ。条件未確定でも3カテゴリ均衡目標を表示可能 | 普段は備蓄目標確認。日曜に在庫を保存、保存済みなら作戦へ進める。イベント設定は必要時だけ |
| イベント開始、条件不足 | **作戦**のコンパクトな不足状態（「未確定：料理・きのみ」等） | 「イベント条件を確定」→必要項目だけ入力→保存。準備へ戻っての重複入力は不要 |
| 条件は確定したが在庫未保存 | **作戦**の短い不足状態 | 「食材在庫を登録」→準備の在庫タブへ直行→保存→作戦へ戻る |
| 条件と在庫が揃い未採用 | **作戦**の短い提案アクション | 「7日間の作戦を提案」→モーダルで7日閲覧→「採用／キャンセル」 |
| イベント中・採用済み | **作戦**の**当日編成を最上部** | 原則操作なし。必要なときだけ「食材在庫を更新」→再提案。設定は小さな入口からのみ |
| 開催後・在庫更新済み | **作戦**の既存採用作戦を保護し、控えめに在庫更新を知らせる | 「残り期間を再提案」→確認→明示採用。勝手に旧作戦を差し替えない |
| イベント終了 | 保存済み作戦を閲覧 | 提案・再提案は禁止 |

**初回表示の推奨場所を使う段階に合わせる**。しかしユーザーが「準備」「作戦」「ボックス」を自分で選んだ後、再描画でその選択を奪わない。作戦内の曜日初期表示はJST04:00、火曜は火曜・水曜は水曜。別曜日閲覧中に戻さない。

## 3. UIの最小構造（必要な時だけ操作が現れる）

### 準備画面
- 先頭は「準備目標｜食材在庫」の2タブのみ。現在の目標アイコン・在庫19項目の4列レイアウトを維持。
- 在庫保存完了は短いトースト。必要時だけ小さく「作戦へ」の導線を出す（大きな説明カードや手順ウィザードを増やさない）。
- 「準備スキル+200/+70」は現行の小ポップアップ。スキルの実績個別入力なし。
- U2ではイベント条件を編集できない。

### 作戦画面：採用前
- 通常の大きな週間編成カードを空のダミーで埋めない。
- 上部に**1行の「未確定・作戦未採用」状態＋必要な1アクション**。「未確定が複数」でも入力一覧を常時展開しない。
- 必要なときだけイベント条件ビューを開き、完了すると作戦画面の主操作は自動で「提案」になる。
- 睡眠設定は既存のコンパクトな「睡眠編成｜自動トグル（初期OFF）｜設定」を維持。

### 作戦画面：採用後・イベント中
- **第1領域：曜日ナビ＋今日の3食/3チーム＋睡眠1晩**を最優先表示。
- 日中21枠・21食は**閲覧専用**。ポケモンアイコンのタップでステータスを見る操作は維持。
- 第2領域：睡眠7晩設定（自動OFF・7晩個別と一括コピー）。設定を開いた時だけ詳細表示。
- 第3領域：必要な場合の在庫更新・再提案。イベント条件の編集入口は小さく、閲覧の妨げにしない。
- 未採用の提案は比較タブに出さず、従来どおり確認モーダル→採用／キャンセル。

## 4. 中断・途中再提案・未確定条件
- 週途中にユーザーが入力するのは**食材在庫のみ**。作戦から在庫更新へ進める場合、準備画面の在庫タブを直接開く。
- 保存が終わったら元の**同じイベント週の作戦画面**に戻れる導線を提示する。自動で再提案・採用は行わない。
- U3側は新しい在庫を検出して、既存採用作戦を残したまま「再提案」を一つ表示。ユーザーが押すと過去/現在の時間帯と料理を固定、未来だけ再計算。再提案のレビュー後に採用する。
- 曜日・食材・イベントデータの保存キーを同じ週で管理。週外の保存済み作戦を勝手に表示しない。
- ワカクサ/EX等の必須条件が未確定ならイベント開始時の提案をインターロック。条件の確定前に偽の提案を出さない。
- 通常備蓄は3カテゴリの最大エナジーレシピを同等優先度で準備。集中イベントは1〜2料理。食数最大化を目的にしない。
- 初期完成版は1週間だけ。2週間用切替は表示しない。

## 5. 具体的なUX受入基準（DOMの並び順では合格にしない）
1. **準備週：** U2の目標を確認→在庫タブで保存。日曜の実績保存済みで「次は作戦」が迷わず分かる。準備でイベント条件を再入力しない。
2. **イベント開始：** 必須条件不足なら不足が即座に分かり、押すボタンが1つ。確定後は追加の重複入力なしに提案→確認→採用。採用した瞬間、当日の作戦が初期表示。
3. **イベント中：** アプリ/作戦を開いた最初の画面で今日の4枠が確認できる。火曜03:59/04:00の境界、水曜の自動表示、別曜日閲覧保持、ページ再読み込みを検証。
4. **在庫更新：** 作戦→準備在庫→保存→同じ週の作戦へ戻る→再提案→レビュー→採用を、途中の迷子・重複入力なしに完結できる。採用前の旧作戦不変、進行中・過去枠は変更禁止。
5. **減算するUI：** 目標と設定の二重表示、無駄なフェーズ説明、段階手動切替、21枠編集、料理手動編集、比較タブ、常時の設定フォームを持たない。
6. **スマホ：** Pixel 7aのChromeで重要な情報が上位に見え、通常操作に大きな説明画面や過度なスクロールがない。320〜430pxでタップ・表示崩れなし。
7. **異常系：** 未保存在庫と0個保存済みは区別、未確定EX/きのみは推測で埋めない、週変更・再読み込み・BFCache・時間経過後の採用を安全に処理。
