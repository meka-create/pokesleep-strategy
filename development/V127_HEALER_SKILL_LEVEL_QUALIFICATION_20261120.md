# v127 回復スキルLvを必須条件にしたヒーラー選出是正（2026-11-20）

## 発見の背景・監査結果
- ユーザー報告：アンバー渓谷で、ボックス内のメインスキルLvが低いツボツボがヒーラーとして採用された。ほかのスキル系ポケモンにも同様の軽視がありうる。
- 原因：F1-Bの \`row.skillLevel\` は \`selectedMainSkillLevel\` としてF4プロフィールへ**正しく到達済み**。しかしF4 \`extract\` とF5 \`healerIds\` は「全体回復のスキルを持つ」という**種類だけ**でヒーラーを候補化していた。F4は後段で回復期待値をエナジー順位へ係数として加えるため、好みのきのみ等で稼ぐ弱い回復個体が主ヒーラーに選出され得た。
- ツボツボの「きのみジュース（げんきオールS）」は確認済みF1-CテーブルでLv1=5、Lv2=7、Lv3=9、Lv4=11、Lv5=15、Lv6=18の1匹あたり回復値。追加で得るきのみジュースは保存・使用の特殊効果を持ち、今回は**ヒーラー維持効果へ仮加算しない**。
- 今回の修正では「げんき100%を前提にした軽量参考モデル」というユーザー方針は維持し、**回復の実際の時系列をシミュレーションしない**。代わりに、採用するヒーラーは最低限のスキルLvと発動期待値を満たすものだけにする。

## v127で実施した是正

1. \`f4/f4-c-auto-v112.js\` に \`assessHealer\` と \`healerPairQuality\` の**共有適格性チェック**を導入。Lvを固定ではなくF1-B実個体の \`selectedMainSkillLevel\` とし、\`f1-c-skill-values-v1.js\` のスキルLv別回復量、実個体の発動確率、基準おてつだい時間から参考回復期待値を計算。ツボツボの特殊スキルもその検証済み回復本体のみ評価する。
2. 意図的に保守的な**参考用ゲート（公式の合格ラインではない）**：スキル1回あたり **15点以上（標準げんきオール相当Lv5/6）**、1日換算 **30点以上**。主の16.5h換算20点以上、副の朝4.5h換算5点以上、主＋副の参考寄与30点以上を全て満たしたペアだけを比較。実際にゲーム内で常時100%が確実に維持されるという保証ではない。閾値は実機とゲーム運用で将来調整可能にする。
3. F4提案の最終比較は**エナジー期待値そのもの**に統一。回復の点数をエナジーへ乗算した旧の \`0.65+0.35×coverage\` は撤廃。回復は「足切り条件」であり、二重にエナジー加点しない。主副右端配置、29窓、睡眠編成の保存、夜間自動ON、採用ゲートは変更しない。
4. \`f5/f5-midweek-v119.js\` も同じ適格性関数でフィルタし、残期間でスキル低レベル個体を新規の主副ヒーラーへ採用しない。変更済み過去スロットや保存済み実績は書換えない。条件を満たす二体がいない場合は**提案をBLOCKED**し、弱い個体で代用しない。
5. ヒーラー以外のスキルLv対応：F4の既存の直接エナジースキルは元々実際のスキルLvで再評価していることを確認。F4/F5の睡眠自動候補・F5残期間の直接エナジーにLv依存を追加。v125の多戦略選抜では料理チャンス／鍋拡張／食材ゲット等、**検証済み効果を持つ支援スキルだけ**が実Lv別効果で支援レーンへ入り、単なる発動確率や未検証効果のスキルを高価値と決めつけない。直接エナジー以外のスキルの週間エナジー換算は依然v125-Bで実装予定。
6. E7プレビューのF4とF5は、合格ヒーラー不足が起きた場合に明確なメッセージを表示し、技術的な理由コードだけに頼らない。E7オフラインキャッシュを更新。**ユーザーの実69個体CSVとニックネームはGitHubへ保存しない**。

## テスト・受入
- \`tests/f4-v127-healer-skill-quality.test.cjs\`：Lv1ツボツボは好みのきのみが極端に強くても主・副へ採用されない。Lv4以下の1回回復量不足、Lv5でも発動期待値不足、Lv5以上＋有効な発動率、きのみジュース特殊効果、ペア不足時のBLOCKED、アンバー渓谷での実提案、回復エナジーの二重計算なし、夜間直接スキルのレベル差を検証。
- \`tests/f5-midweek-v119.test.cjs\`：適格ヒーラー不足の週途中作戦は過去の採用内容を維持し、無理な再編成をBLOCKED。
- \`tests/f4-v125-diversity-oracle.test.cjs\`：支援スキルのLv別効果を使う候補選抜、料理材料の取りこぼし防止を継承。
- 既存F1、F4、F5、E7、v126睡眠編成、備蓄、イベント削除、PWAの全回帰。PR/main CIと公開確認、Android実機受入を別ゲートにする。

## 残る限界
- ヒーラーの「合格」は簡易参考シナリオの**妥当性チェック**であって、現実のげんき100%維持の証明ではない。実ボックスで二体しか合格しない／合格者ゼロの場合に提案不能となるが、不適格なヒーラーの強制採用はしない。ユーザーが閾値緩和を求めた場合は参考条件の変更として明示する。
- 鍋拡張・料理チャンス・食材ゲットを含む間接スキルの週間エナジー期待値比較は**v125-Bの未実装要件**。現時点ではスキルLv別の効果が確認できる候補を有利にスクリーニングするが、最終の週間数値まで完全反映したと偽らない。
- げんき時系列のフルシミュレーション、7晩の完全最適化、F3の双方向最適化は追加しない。v125-Bの最新軽量仕様を優先する。
