# F4-C v102 — 料理パワーアップ・料理チャンス・食材ゲットの状態遷移（2026-11-14）

## 対象と実装範囲
- PR #192 / main `af1c899d127fb1c936fcdecd1428a0a318c5304b` を基準にF4-C v101から継続。
- 既定運用は**朝主＋副ヒーラー、昼夜主1匹、睡眠スコア100・7晩手動編成固定、07:30初操作**。げんき観測/回復履歴は必須化しない。
- 新純粋計算 `f4/f4-c-cooking-skills-v102.js`。既存 `f1/f1-c-skill-values-v1.js` の**確定レベル別効果値**だけを消費。以下の3スキルだけを対象とする：
  1. `Cooking Power-Up S`：次に料理を作るまで持越し、重ねがけ＋200上限。**日曜2倍は基礎鍋にだけ適用**、いいキャンプチケットは（基礎＋拡張）の合計を×1.5、端数は切り上げ。料理が成立した場合だけ鍋拡張を0へ戻す。平日基本鍋33＋10＝43、キャンプ時65、日曜66＋10＝76、日曜＋キャンプ114を基準例にする。
  2. `Tasty Chance S`：＋70%上限、大成功するまでは次の食事に蓄積。成功すれば蓄積0、非成功なら維持。**単純に期待値を次食へ繰り越すのではなく、0〜70各状態の確率質量分布を料理ごとに更新**。大成功率の平日10%／日曜30%は従来どおり仮定と明示し、日曜大成功×3／通常×2を使用。
  3. `Ingredient Magnet S`：**ユーザーが明示した解放済み食材3種類以上**からランダムに3種類選ばれる時の**均等期待量**だけを食材バッグに加算。バッグ満杯や抽選対象未確認はBLOCKED。食材抽選結果・追加食材が確定したと偽らない。特殊な Present・Ingredient Draw などは未対応として拒否。
- `f4/f4-c-item-aware-rank-v101.js`：明示 `cookingSkillScenario='EXPLICIT_TAP_EVENTS_V1'` のときだけ、各朝/昼/夜窓の開始時に**前の編成に残る個体**の指定スキル発動を反映。実発動を推定しない。ゲームで7:30にタップする運用から、料理前に回収→指定発動→編成切替→料理を順に評価。料理していない場合は鍋/料理チャンスを保持。
- `recipeChoicePolicy='GREEDY_AWARE'` のとき、v101の最終候補チームに対して現在庫・鍋拡張で実行可能な料理を毎枠再選択する**局所貪欲参照案**も比較。既存経路どおりの料理案と比べ、スキルによる大型料理の選択を可能にする。ただし完全な全週動的最適化を意味しない。
- E7の `itemAwareReference` 読取専用経路に任意のシナリオ入力を渡し、F4の開発プレビューにスクリプトを追加。既存E7作戦・準備・ボックス、保存構造、正式root、PWAアイコンは無変更。

## 精度・禁止事項
- 新処理は**発動回数・タイミング・個体を明示して試すwhat-ifのみ**。ゲーム内で実際にスキルが発動すると保証しない。複数の候補からの限定再順位付けであり、**完全な先読み全枝探索でも実測の確定エナジーでもない**。全結果 `PROVISIONAL`、`weeklyEnergyCertified:false`、`writesSavedData:false`。
- 料理チャンスが既に上限の分岐を含みスキル発動可否が分岐ごとに異なる場合はBLOCKED。未知の状態を平均化して成功扱いしない。
- いまだ**未接続**：確率スキル発動の実分布・スキル抽選保証、チケット持続/イベント×公式料理補正の端数、実レシピレベル/追加食材の完全値、個体IDの永続保存、正式E7採用、F5の週途中再提案。
- **11/16 04:00配信予定のひとくちナッツ/追加3料理を含む20食材81料理の確定マスターが現段階で未公開**。公式イベント/EXは従来どおりBLOCKED（19/78の中立検証用のみ）。
