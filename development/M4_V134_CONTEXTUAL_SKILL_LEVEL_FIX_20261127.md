# M4 v134 — イベントのメインスキルLv補正と状況依存スキルの分離（2026-11-27）

## Pixel 7a実機で確認した症状
M4 v133で3カテゴリ備蓄の不整合を解消後、実ボックスでイベント週の週間作戦を提案すると「今回の条件では自動提案できません：M1_EVENT_SKILL_LEVEL_UNVERIFIED」と停止する。

## 根本原因
M1 `f4/f4-m1-lite-energy-v128.js` の `withEvent` は、確認済み公式イベントの `skillLevel` 加算時に `skillValue(skill,n)` が直接数値を返すLvだけを列挙して上限を推測していた。**スキル自体の合法Lvと、週エナジーへ数値換算できる効果の有無を混同**していたため、`Metronome`、`Skill Copy (Transform)`、`Versatile`、`Charge Strength S (Stockpile)`、`Helper Boost` 等の状況依存スキルが対象になると上限ゼロと誤認し、**ボックス全体**をBLOCKEDにしていた。

## 修正
1. 上限にはF1-Cの固定 `maxLevel` を使用。既存のF1-B `skillMax` と66対象種族の全22スキルで一致することを代表テストで照合。Lv上限は基礎スキル効果が状況依存でも検証可能。
2. 公式イベント適用対象（とくい・タイプ）のみに `Math.min(上限, 個体の合法Lv+確認済みイベント加算)` を実行する。元の読み取り専用個体プロファイル、保存済みボックス、実個体のLvを改変しない。
3. **状況依存スキルのエナジー・スキルコピー先・げんき・ストック等の効果量は未評価のまま**。M1は合法Lvが分かることだけで数値効果の存在や週エナジーを保証しない。F4/F5は以前と同じF1-C数値表を用い、`CONTEXT_REQUIRED`や`UNSUPPORTED_SKILL`をエナジー加点しない。
4. F1-C上限が不明な未知スキルや偽装されたLv（1未満・上限超過）は引き続きBLOCKED。参照用の一部旧テスト依存注入では直接数値表による既存上限検証を維持。
5. E7開発版専用Service Workerキャッシュを更新。正式root、F3/F4/F5保存形式、69個体CSV・ニックネーム・匿名ID、手動7晩は変更しない。

- 既存M1 v128、ヒーラーv127、F4/F5、F3 v133、ブラウザ・PWA全回帰。
