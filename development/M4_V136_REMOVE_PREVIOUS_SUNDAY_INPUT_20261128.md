# M4 v136 — 軽量版で「前週日曜の5匹」入力を廃止（2026-11-28）

## ユーザー判断
Pixel 7aのM4受入時、睡眠編成に「前週日曜」を手動登録する項目は不要との判断。軽量版では削除する。

## 3時間30分の意味
- Pokémon Sleepのイベント週開始は**月曜04:00 JST**。
- E7 F4-Bの7日168時間のタイムラインは、翌朝07:30までの睡眠を区切るため、**月曜04:00〜07:30の3.5時間**を`PREVIOUS_WEEK_SLEEP`という最初の境界窓として保持する。
- これは**「前週日曜に3.5時間眠れ」というゲーム操作ではない**。ツールの固定168時間・29窓の計算上の区切り。
- この窓の睡眠編成が観測されないなら、**個体・きのみ・食材・スキルによる持越しを確定評価しない**。無関係な月曜睡眠編成を前週実績へ自動転用もしない。

## v136改修契約
1. U3「睡眠編成」カードの`前週日曜`ボタンと登録ダイアログのサブ画面、選択・保存・警告を削除。当週の**月〜日7晩**、自動ON/OFF、5匹選択・7晩コピー・v126共通手動保存は維持。
2. `e7-f4c-integrated-v112.js` は過去の`carry:<週>:<イベント>`レコードを**一切読まず／書かず／削除しない**。`previousCarryRevision:null`に固定し、F4新規提案へ`previousWeekSleepIndices:null`を必ず渡す。`previousWeekCarryUnknown:true`の初期窓に個体5匹を合成しない。古いレコードが壊れていても前週の記録によってボタン無効化・全体の提案停止をしない。
3. **以前の採用済み作戦が「前週日曜は観測済み」で作られていた場合**、その作戦を自動変換・削除せず`STALE_ADOPTED`と表示し、週開始前の通常再提案で新しい未観測条件へ移行する。F5の過去・ACTIVEの予測履歴は勝手に実測扱い／書換えしない。
4. `f4-c-real-storage-v112.js` の`readCarry`/`saveCarry`は**旧バージョンの保存データ互換のため保持**するが、新しいUIから呼ばない。既存の個体CSV、匿名stable ID、イベント・在庫・睡眠テンプレート・プランを削除しない。メインの29窓/168時間と`PREVIOUS_WEEK_SLEEP`時刻枠は変更しない。
5. E7 PWA専用Service Workerのキャッシュバージョンを更新。旧正式rootは変更しない。
