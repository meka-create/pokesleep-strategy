## 実際に確認した問題
1. **P1 開発基盤・mainの監査空白**：E7 v52プレビューはmainに配信済みだが、E7 v51/v52のChromium回帰・先祖返り静的テストとPlaywright環境がmainのCIに無い。 `npm run check`はE7ブラウザ操作を通さない状態だった。
   - 対策：該当E7テストをmain系ブランチに復元、両GitHub ActionsへPython3.12/Playwright1.56.0/Chromium導入を復元。CSV16/17/18列検証も復元。
2. **P1 以前保存した週への再入力が旧イベントで上書きされる**：U3イベント保存処理で`switching`時に`restoreState(d,true)`がフォームから作成した`next`を置換し、そのまま旧フィールド/料理を再保存する。新規Playwright試験で「A週→B週→A週で別フィールドを明示保存」の失敗を再現。
   - 対策：保存済み作戦の復元と、ユーザーが新たに明示入力したイベント条件を分離。入力条件を優先し、旧採用作戦・旧提案の失効判定を保つ。未入力時の正当な既存週復元は維持。
3. **P2 ボックス保存レコードの型検証不足**：`validBox`は`nickname`、食材、サブスキル、まっしろミント、リボン等の型を検査していなかった。人工の不正レコードを正常と判定するテスト失敗を確認。
   - 対策：期待されるstring/null、boolean/null、整数/nullおよび上限を検査。破損レコードは従来どおり上書きをブロック。CSVパーサーが生成する正常データは保持。
4. **P2 ブラウザ試験のロード競合**：タブを開いた直後、iframeのload完了だけを確認して親シェルのloading表示解除を待たない試験経路があった。
   - 対策：ブラウザ回帰のready判定へ親`status.hidden`を追加。ロード中の中間描画を完了と誤認しない。
5. **P2 ロードマップ正本欠落**：E7主系のmainには`development/ROADMAP_CURRENT.md`がなく、E6監査ブランチ内の旧工程のみが正本であった。
   - 対策：旧履歴を保持したまま現行E7とF1–F6の最新ゲートを冒頭に追加、main開発線へ復元。
