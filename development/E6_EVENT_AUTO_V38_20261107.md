# E6 v38: イベント候補の自動取得／プルダウン仮反映／保存確定（2026-11-07）

## ユーザー訂正
ユーザーが不要としたのは「イベント情報を取得」と「選択したイベントを反映」の**ボタン**。イベント候補の自動取得機能は必要。
実際の操作は「候補は自動取得 → イベントを選ぶと**入力欄に即時反映** → 備蓄食材の必要個数へ反映する**確定操作は保存**」とする。

## 実装
- `previews/U3_Strategy_UI_20261107_v38_E6.html`: 開くときに upstream `nitoyon/pokesleep-tool` の `src/data/event.json` を自動取得（HTTP GET、5秒まで）。
- 同梱フォールバックは2026-11-07の同 upstream データのうち2026年の21イベント。オフライン時も選択可能。フッターは従来どおり。取得状況は「最新の公開データを取得／同梱データ」で明示し、失敗を成功扱いしない。
- 期間1週間・月曜04:00開始のイベントだけを候補化し、2週連続を勝手にまとめない。
- プルダウン変更時は`pendingEventSource`のみに保持、開始日や大きな補正表示は**未保存の仮反映**。日付変更と同時に旧イベントのフィールド/料理を使い回さない。
- 保存ボタンで初めて、選択したsource/イベントID/条件台帳を確定。**選ぶだけでは localStorage に一切書かない**。日付が選択候補と異なる場合は保存エラーとする。
- 保存済みsourceやキャンプOFFは維持。古いデータとの互換性を壊さない。通信で候補更新しても選択中／既存保存中のsourceを消さない。
- 候補の補正値は upstream で意味が明確な項目のみ表示。詳細不明は「要確認」。E6の例示計算に補正倍率を勝手に適用しない。
- **F3の正式備蓄レシピ計算は未実装**。本v38で選択変更は必ず保存まで備蓄目標に影響しない。保存後に必要食材数を実際に算出して表示する後続統合はF3で実施し、E6で完成したように見せない。
- 旧v37/E5/mainは変更しない。U2/U4はv38へのナビリンクのみ更新。
- 自動テスト: 新規 JS静的契約＋Chromeオンライン模擬/オフライン/選択プレビュー・保存後確定・データ保護。
