# ポケスリ作戦室 — U3 作戦画面 UI設計（2026-11-03）

## 位置づけ
U3は**1週間イベント専用のUI設計と操作モック**。計算機能・実データ連携は行わない。U2は設計完了として維持。設計ブランチはmainとDraft PR #109とは別。

HTML: `previews/U3_Strategy_UI_20261103.html`

## 画面構成
- イベント条件（折りたたみ）：月曜開始日・フィールド・料理カテゴリ・いいキャンプ。通常鍋容量・フィールドボーナス・バッグ容量は別の「登録」画面。
- 睡眠も自動提案：デフォルトOFF。次に生成する提案へ反映。
- 「7日間の作戦を提案」ボタン。
- 生成した場合のみ「運用中／提案」切替と「この作戦を採用／破棄」。
- 月～日曜を7ボタンで切替。選択日の朝・昼・夜・睡眠それぞれ5匹を表示。
- 朝昼夜は料理を表示し、編成の編集モーダルで5匹とレシピを変更できる。
- 睡眠は7晩個別変更／選択した晩の編成を7晩にコピー。差分を残しやすい。
- 週間エナジーは「—」の仮表示。未確定計算を仮数値で見せない。

## 保護ルール
- 提案を生成しても**運用中は変更しない**。提案への編集も運用中に影響しない。
- 採用で初めて運用中へ反映。提案を破棄できる。
- 5匹を揃えた場合のみ編集保存。個体の重複不可。
- 手動睡眠7晩は、自動睡眠ONにして生成・採用した後も別に保護する。OFFで再提案すると手動7晩を再利用する。
- 手動で編集した提案を再生成する場合、および別内容の睡眠編成を7晩へコピーする場合、上書き確認を行う。
- イベント条件変更時は提案を無効にする。現在の編成は**旧条件**と明示し、元データを上書きせず再提案を促す。
- 期間は常に7日間。14日間や第2週のUIは作らない。

## 操作モックの制限
- ポケモンは見本12個体。二文字の仮アバターで表示し、実装時はユーザーボックスから実個体と画像を取得する。
- 料理はカテゴリ別の見本リスト（4品ずつ）。目標食材・素材消費・実際のエナジーは計算しない。
- ページ内状態のみ。ブラウザ再読み込みで初期化。今後の統合工程で永続化。
- 外部画像・JavaScript参照なし。オフライン表示が可能。

## 試験結果
Chromium（360 / 390 / 430px）で全幅PASS。曜日7ボタン、朝昼夜＋睡眠の4枠、提案／運用中の分離、採用、5匹選択・料理編集、手動睡眠保持、7晩一括コピー、スクロールはみ出しを確認。イベント条件の不正曜日拒否／変更後旧条件保持／再提案・採用もPASS。

## U3 UI改訂 v3（2026-11-03）

- 料理・フィールド・レシピは独自プルダウン（キーボード操作、外側タップで閉じる、スクロールバー非表示、選択強調）。

- Chromium 360/390/430pxで表示・操作試験PASS。PokéAPIのサンプル12画像の存在確認PASS。画像取得制御は擬似HTTPで12種13リクエスト（1回の429を含む）、キャッシュ12件、最大同時3件以内、150ms開始間隔を確認。
- **保留**：実端末でのPokéAPI画像取得・OS再起動後キャッシュ確認、ユーザーボックスデータの連携。計算と保存の新規実装は引き続き保留。

## U3 UI改訂 v4（2026-11-03）

- **イベント途中の再提案**：月～日の経過済み時間帯と料理を変更せず、残りの枠だけ提案。提案と運用中の編成は分離し、採用時も開始済みの枠を再判定して保護する。終了後は提案を無効化。
- **時刻基準（操作モック限定）**：日本時間で朝7:30、昼12:00、夜18:00、睡眠22:00を仮の開始時刻として保護する。特に22:00は就寝時刻の**未確定の試験用仮値**。正式計算で使用するルールはUI承認後に設計する。プレビューURLに `?previewNow=2026-11-11T17:39` を付けて模擬できる。
- **途中再提案の精度の制限**：最新の食材在庫・げんきなどを未取得の場合、実ゲームに即した残り期間の計算を保証しない。現段階はUIの動作設計のみ。
- **トグルの修正**：従来のキャンプ側はCSSの `.field input[type=checkbox]` がチェックボックスの寸法を上書きしていた。両スイッチとも48px以上の行全体をタップできる `button role="switch"` に更新。ON/OFFテキストは不要。
- **ヒーラーの配置**：メインを右端、セカンドを右から2番目。モックはサーナイトとニンフィアをそれぞれ仮のメイン／セカンドとして並べ替える。実装時は種族固定でなくユーザーの**個体・役割**に基づく判定を別途設計する。
- **表示の簡素化**：「朝・昼・夜・睡眠」の重複見出しを削除。各編成カードは時間帯のみ表示し、スクリーンリーダー用の枠名称を保持。
- **ステータスモーダル**：`nitoyon/pokesleep-tool/src/ui/IvCalc/IvForm/IvForm.tsx` の項目の流れを参考に、ポケモン・レベル・食材・おてつだい時間・最大所持数 → メインスキルとLv10/25/50/70/80の2列サブスキル → 詳細ステータス（せいかく・睡眠時間）の順に配置。実情報不明の項目は推測せず「—」。
- **試験**：GitHub版と同一の操作JavaScript（FNV32一致）を含むHTMLを使用してChromiumの360/390/430pxで試験し、スイッチ両端タップ、保存・再提案、ヒーラー順、モーダル、途中再提案・採用時の時間経過保護をPASS。週終了後の提案無効化・手動睡眠7晩保持・残り夜への一括設定もPASS。画像は通信制限のある検証環境では文字フォールバックで確認。本番Android実機試験は未実施。
- **U3状態**：操作モック改訂済、ユーザー受入待ち。mainとDraft PR #109は変更なし。

## U3 UI改訂 v5（2026-11-03）

### 配置の統一
- イベント条件カード内部の余計な横パディング（12px）を削除。**「いいキャンプチケット」と「睡眠も自動提案」の文言位置／スイッチ右端を揃える。**
- **「保存」と「7日間の作戦を提案」の左右端を同じ幅に揃える。**
- 両トグルは、行のどこをタップしても切替可能なボタンのまま維持。

### ステータスモーダル
- 冒頭の重複見出し（例「デデンネ · ステータス」）は画面から削除。スクリーンリーダー向けタイトルだけ非表示で保持。
- ニックネームの下にだけポケモンのレベルを表示。ポケモンの種類とレベルの重複を解消。ニックネームと種族が同一なら種族の重複行も非表示。
- 食材はU2で採用した**19種類の独立した透過PNGアイコンをHTMLへ埋め込み**、詳細画面では該当する3枠をアイコン＋名前＋解放Lvで表示。**表示時の画像URL参照なし**。3枠の画像行は横幅いっぱいにして文字の折り返しを軽減。
- メインスキルはカード枠をやめ、余計な背景のない一行表示（スキル名とLv）に変更。サブスキル5枠は既存2列を維持。
- ポケモンアイコンは引き続き既存のPokéAPI基本ルールで取得・キャッシュ。アイコンタップで状態表示、編成の選択／解除は別操作。

### イベント条件の編集場所（今後の本番統合で厳守）
- **新UIではイベント固有の条件を編集する場所は「作戦」画面のイベント条件カードだけ。**
- 開始日、開催フィールド、料理カテゴリ、いいキャンプチケットをここで編集。
- **「準備」は条件の要約を参照するだけで再入力しない。「ボックス」にはイベント条件を置かない。**
- 個人データ（フィールドごとのボーナス、通常鍋容量、バッグ容量）は別の「登録」画面で編集。
- 現行mainの旧イベント入力UIと旧計算設定UIは**U5統合時に表から撤去し、一元化する**。それまでは保存済みデータと互換処理を保護。今回の変更はU3設計用モックのみで、mainとDraft PR #109は変更しない。
